## Issues resolved

**Deadlock and deadline wording.** The first code review found that the README attributed removal of circular wait to ordered mutex acquisition, although the implementation's atomic pair acquisition is what prevents a coder from holding one dongle while waiting for another. It also said burnout required exceeding the deadline, while the monitor detects it once the interval is reached. The README explanations were corrected to distinguish these contracts and re-review approved them. No production code or acceptance criteria changed.
