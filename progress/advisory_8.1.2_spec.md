Advisory only: no files changed, no make, gate or seal performed. References to **spec** mean `docs/plan/phase-08-monitor/8.1.2-get-target-met.md`.

1. **Contract is sound overall.** Validation before the zero-target shortcut, `>=` comparisons, one mutex at a time, and publishing `*met` only after successful unlock match the proposal and subject. Monotonic counts make a positive result sound; a negative result can become stale immediately, which is normal for a monitor scan. No additional locking is needed (`spec:29–44`; `progress/phase08_tasks_proposal.md:36–40`; `docs/codexion-rules.md:213`; `coders/src/coder/set_compile_count.c:22–30`).

2. **AC1 — deterministic and correct, with a capture precaution.** Its configuration is valid and initialization supports it. Field comparisons and post-call `trylock` checks are suitable sealed assertions. The hang guard must cover the calls themselves: excessive erroneous output can fill the pipe **before** the drain begins. Compare named initialized fields, never whole structs containing mutexes or uninitialized thread handles (`spec:10`; `coders/src/init/init_coder.c:24–31`; `coders/main.h:83–93`).

3. **AC2 — deterministic and correct, but its coverage claim is wrong.** All listed results follow the contract, including `INT_MAX`. However, none isolates the **last coder below target**: an implementation scanning only indices 0–2 passes every listed case. Add `3, 3, 3, 2 → met == 0`; remove or correct “the first and the last coder are both inspected” (`spec:11`).

4. **AC3 — deterministic, constructible and correct.** `parse_config` accepts one coder, target 2 and `edf`; `init_simulation` builds one coder and one dongle, with both dongle indices equal to 0. Manually seeded counts test this helper’s predicate correctly, although a live single coder cannot complete a compile requiring two dongles. State explicitly that this is a synthetic state test without worker threads (`spec:12`; `coders/src/parsing/get_arg_minimum.c:17–20`; `coders/src/parsing/parse_mode.c:21–24`; `coders/src/init/get_dongle_pair.c:21–33`; `docs/codexion-rules.md:112`).

5. **AC4 — deterministic, constructible and correct.** Target 0 is accepted at argument position 6; initialization does not reject or short-circuit it. The expected result agrees with PLAN’s immediate clean termination. Add **one coder with target 0** if that combination is intended explicitly. “No mutex locking for zero” correctly remains a source-review obligation (`spec:13,19`; `coders/src/parsing/parse_config.c:34`; `coders/src/parsing/get_arg_minimum.c:19–20`; `coders/src/init/init_simulation.c:35–46`; `docs/plan/PLAN.md:140–150`).

6. **AC5 — correct expected result, but not a deterministic proof of contention.** The worker may be descheduled after its handshake and enter the function only after unlock; it can therefore pass without demonstrating blocking. The spec already acknowledges this limitation, consistently with the sibling advisory. Keep it as supplementary concurrency evidence and keep lock placement in code review. The 2000 ms join guard is a liveness budget, potentially fragile under instrumentation; define instrumentation-aware limits, and ensure the handshake wait is bounded too (`spec:14,17`; `progress/advisory_8.1.1_spec.md:17`; `progress/phase08_tasks_advisory.md:10`).

7. **AC6 — deterministic and correct; clarify its exception to preconditions.** These tests deliberately corrupt an initialized simulation despite the immutable-configuration precondition. Explicitly say the named invalid inputs remain guaranteed rejection cases outside normal preconditions. Include a **negative coder count**, since the contract/review requires `< 1`, whereas AC6 tests only 0. Restore all mutated fields before cleanup (`spec:15,19,38–41`).

8. **Missing coverage / review allocation.** Add another **positive target**, preferably `INT_MAX` with counts `INT_MAX - 1` and `INT_MAX`, to reject hardcoded target 3 and check the upper boundary; AC3’s target 2 helps, but only exercises the single-coder path. Extend preservation assertions to named coder identity/dongle fields and apply shared preservation/unlocked checks across success cases. Lock/unlock errors, validation-before-lock, zero-target no-lock behavior, forbidden locks and absence of allocation/logging/clock calls appropriately stay in code review under the stated no-injection harness (`spec:10–19`; `docs/conventions.md:110–115`).

9. **Naming/conventions: no substantive issue.** `get_target_met`, the 0/−1 return with an out-parameter, filename, layer and Monitor section comply. The three production files and linear sibling dependency match the proposal. README deferral follows the sibling precedent because this helper adds no user-visible behavior (`spec:4–8,46–53`; `docs/conventions.md:31–33,49–53,85–86,110–112`; `progress/phase08_tasks_advisory.md:5`).
