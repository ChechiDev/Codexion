# 8.1.1 spec — Codex advisory review (2026-11-05)

Advisory only (no gate, no seal). Applied in docs/plan/phase-08-monitor/8.1.1-get-burned-out.md.

Advisory only; no files changed, no `make`, gate or seal performed. References below use **spec** for `docs/plan/phase-08-monitor/8.1.1-get-burned-out.md`.

1. **Contract: sound overall, but tighten preconditions.** The `>=` boundary, protected clock/state snapshot, satisfied-coder behavior and publication after successful unlock match the subject and proposal (`docs/codexion-rules.md:133`, `:137`; `progress/phase08_tasks_proposal.md:30`). However, `init_simulation` validates only the coder count and copies the remaining configuration (`coders/src/init/init_simulation.c:35`). Explicitly require a validated, immutable configuration, particularly `time_to_burnout >= 1`. Also require `burned` to reference writable storage outside coder/simulation fields; otherwise an alias such as `&coder->compile_count` contradicts “no field … is written” (spec:19, :47).

2. **AC1 — deterministic and correct, with capture precautions** (spec:10). **Yes: `start_ms = LONG_MAX` clamps elapsed to 0**, assuming a successful, representable clock read (`coders/src/time/get_elapsed_ms.c:19–24`). Thus `-799/-800/-801` correctly yield `0/1/1`. This follows the established clamp test in `7.1.1-set-compile-start.md:12`. For the sealed oracle, restore/close the redirected stdout writer before draining to EOF; use a hang guard because draining only after calls can deadlock on excessive erroneous output.

3. **AC2 — correct expected behavior, but not deterministic** (spec:11). Descheduling for ≥800 ms after renewal can legitimately produce `burned == 1`; backward wall-clock changes can invalidate the first assertion. It also omits explicit return-code assertions. Prefer controlled-clock cases for the sealed correctness oracle; retain this as a qualified real-clock smoke test if useful.

4. **AC3 — deterministic, testable and correct** (spec:12). It correctly rejects a per-coder target exemption: termination requires **all** coders to meet their targets (`docs/codexion-rules.md:137`). Explicitly assert return 0 and retain the other coders below target so the scenario is unambiguous.

5. **AC4 — values correct; UBSan feasible only with an explicit instrumented rebuild** (spec:13). At elapsed 0, `LONG_MIN → 1`, `LONG_MAX → 0` are correct. Direct subtraction in the displayed contract would overflow for `LONG_MIN`; identify it as mathematical notation or use the safe comparison already specified at spec:19. The harness accepts `EXTRA_CFLAGS`, but object freshness does **not** depend on compiler flags (`Makefile:10`, :33). Adding UBSan only when linking the test leaves production arithmetic uninstrumented. Specify a separate build directory or fresh object rebuild, instrument both production objects and test, and use nonrecovering UBSan or check diagnostics. No root Makefile change is inherently necessary.

6. **AC5 — useful contention check, but neither deterministic nor conclusive** (spec:14). The handshake occurs **before** entering the function: the worker could remain unscheduled for 50 ms, so `done == 0` does not prove blocking. After renewal, scheduling delay can also make `burned == 0` false legitimately. The 1000 ms guard is a liveness timeout, especially fragile under instrumentation. This inherits the limitation of `7.1.1-set-compile-start.md:13` and conflicts with the “no probabilistic sleeps” recommendation (`progress/phase08_tasks_advisory.md:10`). Use clamped time for the renewed-value result; keep actual lock placement/order in source review unless deterministic instrumentation is introduced.

7. **AC6 — deterministic, testable and correct** (spec:15). Construct the NULL-`sim` case from an initialized coder, restore its pointer before cleanup, and snapshot named initialized fields rather than comparing entire structs containing mutexes, padding or an uninitialized thread handle (`coders/src/init/init_coder.c:24`). Review still establishes validation before clock/lock access.

8. **Missing coverage / review allocation.** Add explicit cases for the actual initial `last_compile_start == 0` (`coders/src/init/init_coder.c:29`), a different valid burnout duration to reject hardcoding, and unrelated-coder state preservation. Keep lock scope, forbidden locks, allocation/logging absence and failure cleanup in code review (spec:19). Clock/lock failures are not deterministically forceable through ordinary valid inputs, but spec:17’s absolute claim is too broad: linker wrapping or a dedicated fault-injection build can force them. Choosing review coverage follows the 7.1.1 precedent, but differs from the advisory’s proposed fault tests (`progress/phase08_tasks_advisory.md:10`).

9. **Naming/conventions: no substantive issue.** `get_burned_out`, 0/−1 with an out-parameter, the `monitor/` module and Monitor header section comply (`docs/conventions.md:49`, :85, :110; `docs/plan/PLAN.md:59`). The stronger “output unchanged on unlock failure” guarantee appropriately differs from the mutating setter (`7.1.1-set-compile-start.md:18`). README deferral is consistent with that precedent.
