## Description

`int print_log_line(t_sim *sim, int coder, const char *text)` in
`coders/src/log/print_log_line.c`, declared by 3.4.5 (contract there): the
single output path of the logger. The caller holds `log_mutex`; the helper
reads the timestamp, builds the line and sends it with one unbuffered `write`
(PLAN.md "Log"). It takes no lock and does not look at the stop flag: deciding
whether a line may be printed (stopped check, first-stop claim) stays in the
callers, `print_state` (3.4.3) and `print_burnout` (3.4.4).

In the same step `print_state.c` drops its own copy of the sequence and calls
`print_log_line`, so the code never holds two output paths. Its observable
behaviour is unchanged (sealed oracle `test_3.4.3.c`).

**Naming fix.** The 3.4.3 static helpers `write_line` and `read_stopped` use
verbs outside the closed list of `docs/conventions.md` (not flagged at its
code gate). `write_line` disappears; `read_stopped` is renamed with an allowed
verb (e.g. `get_stopped`). This subtask supersedes those names; 3.4.3 stays as
delivered (commit, spec, reference doc).

**Return contract (follows `docs/conventions.md`).** 0 if the whole line was
written; -1 if the clock, the line build (`coder` < 1, invalid text) or
`write` failed. A short or failed `write` may leave partial output.

**README.** No close-time update (no user-visible change until phase 09).
