## Description

**Type.** `main.h` gains `# include <pthread.h>` right after the header guard
(allowed since PR #8, `docs/conventions.md`) and a first, minimal `t_sim` in
the Types section:

    typedef struct s_sim
    {
        long            start_ms;     /* epoch ms of the simulation start (3.1.1) */
        int             stopped;      /* 0 running, 1 stopped; guarded by stop_mutex */
        pthread_mutex_t stop_mutex;
        pthread_mutex_t log_mutex;    /* serializes the output (3.4) */
    }   t_sim;

Only what phase 03 needs. Until phase 05, the tests init and destroy the
mutexes themselves.

**Invariants (phase 05 must keep them).** `sim` is never NULL; both mutexes
are successfully initialised (default, non-robust) before any thread uses
them and destroyed only after every user has finished; `stopped` is always 0
or 1 and starts at 0; `start_ms` is set before any worker thread runs. Phase
05 keeps these fields and meanings when it extends `t_sim` (config, coders,
dongles), unwinds partial initialisation, and never copies an initialised
`t_sim` (pass it by pointer).

**Function.** `int is_stopped(t_sim *sim)` in `coders/src/state/is_stopped.c`:
locks `stop_mutex`, reads `stopped`, unlocks, returns 1 if stopped, 0
otherwise. It is the public reader of the flag (coders, sleep, monitor); every
concurrent access to `stopped` holds `stop_mutex`. Code that already holds
`stop_mutex` (e.g. the atomic stop-and-print of 3.4.4) reads the field
directly instead.

**Error contract: a justified exception (user decision, 2026-10-28).**
`docs/conventions.md` asks for a 0/-1 status with an out-parameter. As a yes/no
predicate, `is_stopped` returns 1 ("stopped") if `pthread_mutex_lock` or
`pthread_mutex_unlock` fails: a thread that cannot read the flag safely stops
its own work instead of running on with unknown state. This does **not** set
the shared flag, wake other threads or guarantee the clean shutdown and
non-zero exit of `PLAN.md`; those belong to phases 05-09. The "leaves the mutex
unlocked" guarantee holds only when both mutex operations succeed.

**Lock rules.** Lock order is `log_mutex → stop_mutex` (3.2.2, 3.4).
`is_stopped` takes only `stop_mutex` and never `log_mutex`, so it cannot break
that order. It must not be called while already holding `stop_mutex`, and
`set_stopped` (3.2.2) must not be called while already holding `log_mutex`.

**Why `src/state/`.** The stop flag is shared simulation state read by coders,
sleep, logger and monitor, so it does not belong to any one of them (`utils/`
excludes domain types). Close-time documentation: `docs/architecture.md` gains
this folder's row.

`main.h` gains a `/* ---- State ---- */` section after `Time` and before `CLI`.
`pthread_mutex_trylock` and `PTHREAD_MUTEX_ERRORCHECK` are test-only; they are
not in the subject's allowed list and never appear in `coders/`.

**Supersedes.** This subtask supersedes the "no system header in `main.h`" rule
delivered by 2.2.3 (convention changed in PR #8, `docs/conventions.md`:
`main.h` includes only `<pthread.h>`). 2.2.3 stays as delivered (commit, spec,
reference doc).
