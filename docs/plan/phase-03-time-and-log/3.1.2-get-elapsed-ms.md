## Description

`long get_elapsed_ms(long start_ms)` in `coders/src/time/get_elapsed_ms.c`:
milliseconds elapsed since `start_ms` (an epoch time from `get_time_ms`, 3.1.1),
i.e. `get_time_ms() - start_ms`. It is the `timestamp_in_ms` of every log line
(subject 5.1), with `start_ms` the common simulation start, so the first line
can print `0` as in the subject examples (5.2, 6.2).

It takes the start as a plain `long`, not a `t_sim`, so it depends only on the
clock and is testable without any shared state.

- **Never negative:** `gettimeofday` is wall-clock time and can jump backwards
  (e.g. an NTP adjustment). If the current time is before `start_ms` it returns
  0, so a log line never shows a negative timestamp. "Never negative" applies
  to successful results; -1 is reserved for a clock failure (below).
- **Clock failure:** if `get_time_ms` returns -1 (3.1.1, cannot happen in
  practice), it returns -1, checked before the subtraction. Same justified
  exception to the 0/-1 + out-parameter convention as 3.1.1.
