## Description

First of two steps that remove the duplicated output sequence found in the
3.4.4 code review (`progress/review_3.4.4.md`): `print_state` (3.4.3) and
`print_burnout` (3.4.4) both need "read the timestamp, build the line, one
`write`". The shared helper is declared here and extracted in 3.4.6, which
also switches `print_state` to it in the same step, so the code never holds
two copies of the sequence.

**Contract of `print_log_line` (implemented in 3.4.6).** `int
print_log_line(t_sim *sim, int coder, const char *text)`: the caller already
holds `log_mutex`. It reads `ts = get_elapsed_ms(sim->start_ms)` (3.1.2),
builds the line with `build_log_line` (3.4.2) into a local
`char line[LOG_LINE_MAX]`, and sends it with exactly one `write(1, line, len)`
with no retry. Returns 0 only if `write` returned `len`; -1 if the clock, the
build or the `write` failed (no `write` when `ts` or `len` is -1). It never
locks or unlocks any mutex and never reads or changes `stopped`.

Only the declaration is added: no source file, no `Makefile` change, no
behaviour change. The 42 header `Updated:` line of `coders/main.h` is
refreshed with Stdheader (`docs/conventions.md`).
