## Description

`int build_number_text(long n, char *buf)` in
`coders/src/utils/build_number_text.c` (core: no output, no allocation, no
pthread, no clock): writes the decimal digits of a non-negative `n` at the
start of `buf` and returns how many it wrote. `snprintf` is not allowed, so the
logger needs it to put the timestamp and the coder number in a line sent with
one `write` (PLAN.md "Log", user decision 2026-10-28; used by `build_log_line`,
3.4.2).

- **Capacity.** A non-NULL `buf` must provide `NUMBER_TEXT_MAX` writable bytes
  (20, a `main.h` macro: the 19 digits of `LONG_MAX` plus one spare). The
  signature cannot detect a smaller buffer; that is outside the contract.
- **LP64 assumption.** 20 bytes and the 19 digits of `LONG_MAX` hold for the
  64-bit `long` of the evaluation platform (LP64 Linux), as in 3.1.1; they are
  not universal properties of C's `long`.
- **No sign, no terminator.** It writes no `'\0'`: the caller appends the rest
  of the line and passes the total length to `write`.
- **Invalid input.** `n < 0` or `buf == NULL` → returns -1 and writes nothing.
  The log never prints negative numbers (elapsed time is never negative, 3.1.2;
  coders are 1-based), so a negative value is a caller error, reported instead
  of printed.
- **Generic.** It knows nothing about coders or logs, so it lives in `utils/`
  (`docs/conventions.md`, Utils) and can serve any later number output.

**Return contract: a justified exception (user decision, 2026-10-28).**
`docs/conventions.md` asks for a 0/-1 status with an out-parameter. This
helper returns the digit count (>= 1) or -1 instead: the count is exactly what
the caller needs to append the next part of the line, and -1 cannot be mistaken
for a count.
