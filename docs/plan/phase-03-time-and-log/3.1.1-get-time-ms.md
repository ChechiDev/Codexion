## Description

`long get_time_ms(void)` in `coders/src/time/get_time_ms.c`: the current
wall-clock time in milliseconds since the epoch, from `gettimeofday` (allowed;
the subject recommends it, 5.2). It computes `tv_sec * 1000 + tv_usec / 1000`
in `long`, which is 64-bit on the evaluation platform (LP64 Linux), so epoch
milliseconds never overflow. `<sys/time.h>` is included in the `.c` file, not
in `main.h`.

It is the only place that reads the clock: the time relative to the start
(3.1.2), the sliced sleep (3.3), the logger (3.4) and later the dongle cooldown
and the monitor all build on it.

**Error contract: a justified exception (user decision, 2026-10-28).**
`docs/conventions.md` asks for a 0/-1 status with an out-parameter. The clock
returns its value directly instead: the only read error of `gettimeofday` is
`EFAULT` (invalid pointer), impossible with the local `struct timeval` used
here, and a status return would spread never-taken error branches through every
time computation of phases 03-08 under the Norm's 25-line limit. The syscall
result is still checked: if `gettimeofday` fails, the function returns -1 (no
valid epoch time is negative). Every caller checks it before any arithmetic:
`get_elapsed_ms` (3.1.2) returns -1, `sleep_ms` (3.3.1) returns -1, and the
loggers (3.4.3, 3.4.4) skip the `write` and return -1.

`main.h` gains a `/* ---- Time ---- */` section after `Parsing` and before
`CLI` (sections follow the layer order: core, adapters, interfaces).
