## Description

`int pop_request(t_heap *heap, t_request *out)` in
`coders/src/heap/pop_request.c`: removes the head of the min-heap (the request
served first) and copies it into `*out`, then restores the heap order with a
static `sift_down`. With push (4.3.1) and peek (4.3.2) it completes the
hand-written priority queue (subject 6.1.11).

**Algorithm.** Copy `items[0]` to `*out`; decrement `size`; if elements remain,
move `items[size]` to the root and, while it has a child that
`is_request_before` it, swap it with the smaller child. Children are computed
only after checking `i < size / 2` (so `2 * i + 2` cannot overflow):
`left = 2 * i + 1`, `right = left + 1`, the right child read only when
`right < size`. O(log n) comparisons.

**Use in phase 06.** Under the PLAN.md "head of both" rule, a coder pops only
when its request is the head of both dongle heaps (checked with
`get_head_request`), so `pop_request` always removes that coder's own request;
no remove-by-coder operation is needed. On stop, queued requests are not
popped: the heaps are freed after the threads are joined (4.2.2).

**Return contract (follows `docs/conventions.md`).** 0 on success; -1 if
`heap` or `out` is NULL or the heap is empty (`size == 0`). On -1 neither
`*out` nor the heap is modified.

**Preconditions.** A non-NULL `heap` was initialised by `init_heap` and not
freed, and `items[0..size)` satisfies the heap property (written only by
`push_request`/`pop_request`). A non-NULL `out` points to writable `t_request`
storage that overlaps neither `*heap` nor its backing array. No locking: the
caller holds the dongle mutex.

Pure core (PLAN.md layers). Close-time documentation: the `heap/` row of
`docs/architecture.md` mentions it; phase 04 is complete.
