## Description

**Type.** `main.h` gains, in the Types section:

    typedef struct s_request
    {
        long    key;      /* fifo: arrival ticket; edf: deadline (4.1.2) */
        long    ticket;   /* arrival ticket, unique per request (tie-break) */
        int     coder;    /* 1-based id of the requesting coder */
    }   t_request;

It is the element of the dongle heaps (4.2, 4.3). A coder pushes the same
`(key, ticket)` into the heaps of both its dongles (PLAN.md "Acquisition"), so
the order must not depend on anything else.

**Function.** `int is_request_before(const t_request *a, const t_request *b)`
in `coders/src/policy/is_request_before.c`: returns 1 if `a` must be served
before `b`, that is `a->key < b->key`, or equal keys and
`a->ticket < b->ticket`; otherwise 0. It is the single comparator of the heap
(4.3) and of the arbiter (phase 06).

- **Strict order.** Equal `(key, ticket)` gives 0 both ways. Each logical
  acquisition request receives one simulation-wide, strictly increasing
  arrival ticket. Both heap entries of that request carry the same `key`,
  `ticket` and `coder`, unchanged while queued; retries of the same queued
  request keep its ticket. Distinct logical requests have distinct tickets, so
  the order is total over distinct logical requests (the two copies of one
  request compare as equivalent), which the PLAN.md progress argument needs.
  Phases 05/06 own the synchronized ticket assignment and must prevent counter
  overflow.
- **Fifo and edf in one rule.** Under fifo `key == ticket`, so the order is the
  arrival order; under edf the closest deadline wins and ties go to the earlier
  arrival (subject 6.1.5, PLAN.md "Arbitration keys").
- **No overflow.** Fields are compared with `<`, never subtracted, so any
  `long` value is safe (AC5).
- **NULL.** If either pointer is NULL it returns 0 without dereferencing
  either pointer (AC7). This defensive result does not define ordering or
  equality for NULL. Heap and arbiter callers always pass non-NULL pointers to
  live, fully initialized requests, with no concurrent modification during the
  comparison.

Pure core (`docs/architecture.md`, PLAN.md layers): no pthread, clock, output
or allocation. Close-time documentation: `docs/architecture.md` gains the
`policy/` row.
