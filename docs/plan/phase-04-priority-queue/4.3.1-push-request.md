## Description

`int push_request(t_heap *heap, const t_request *req)` in
`coders/src/heap/push_request.c`: inserts a copy of `*req` into the binary
min-heap (4.2.1) and restores the heap order with a static `sift_up`. After the
call `items[0]` is the request that must be served first among those queued
(subject 6.1.11: hand-written priority queue for fifo/edf).

**Algorithm.** Place the copy at `items[size]`, increment `size`, then while
the new element is not at the root and `is_request_before(new, parent)`, swap
it with its parent (`(i - 1) / 2`). O(log n) comparisons; with the capacity 2
of a dongle heap (phase 05) that is at most one swap.

**Return contract (follows `docs/conventions.md`).** 0 on success; -1 if
`heap` or `req` is NULL or the heap is full (`size == capacity`). On -1 the
heap is not modified.

**Preconditions.** A non-NULL `heap` was initialised by `init_heap` and not
freed; `items[0..size)` already satisfies the heap property (only this module
writes it); `*req` is fully initialised. The heap accepts any `long` key and
ticket without policy validation; phase 06 callers check `get_request_key`
for -1 (4.1.2) before enqueueing. A non-NULL `req` points to readable
`t_request` storage that overlaps neither `*heap` nor its backing array. No
locking: the caller (phase 06)
holds the dongle mutex that guards the heap.

Pure core (PLAN.md layers). Close-time documentation: the `heap/` row of
`docs/architecture.md` mentions it.

**README.** No close-time update (no user-visible change until phase 09).
