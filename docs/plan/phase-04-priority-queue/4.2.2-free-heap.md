## Description

`void free_heap(t_heap *heap)` in `coders/src/heap/free_heap.c`: releases the
array of a heap created by `init_heap` (4.2.1) and resets it to the empty,
non-live state `items = NULL`, `size = 0`, `capacity = 0`.

- **Safe to repeat.** Because the fields are reset, a second call frees NULL
  and changes nothing (AC3). The phase 05 teardown can therefore free every
  dongle heap on any cleanup path, including after a partial initialisation.
  Phase 05 must initialise every heap that cleanup may visit to NULL/0/0
  before any fallible initialisation step. A failed `init_heap` leaves that
  state unchanged; a failed `init_heap` on garbage storage does not make that
  storage safe for `free_heap`.
- **Pending requests.** The requests are stored by value, so releasing the
  array releases them all; nothing else is owned. Under the PLAN.md design a
  heap is freed only after every thread is joined (no concurrent access).
- **NULL.** `free_heap(NULL)` does nothing.

**Precondition.** A non-NULL `heap` is either zeroed, reset by `free_heap`, or
initialised by `init_heap` (its `items` was returned by `malloc` and not freed
elsewhere). An uninitialised struct with garbage fields must not be passed.

**Return contract.** `void`, as `print_usage`: there is no failure to report
(`free` has no error result) and the reset state is observable through the
fields.

Pure core (PLAN.md layers). Close-time documentation: the `heap/` row of
`docs/architecture.md` mentions it.

**README.** No close-time update (no user-visible change until phase 09).
