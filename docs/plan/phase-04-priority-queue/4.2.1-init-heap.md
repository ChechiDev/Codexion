## Description

**Type.** `main.h` gains, in the Types section after `t_request`:

    typedef struct s_heap
    {
        t_request   *items;     /* malloc'd array of capacity slots */
        int         size;       /* used slots, items[0] is the head */
        int         capacity;   /* fixed at init */
    }   t_heap;

A binary min-heap stored in an array (subject 6.1.11: the scheduling priority
queue is hand-written): the children of slot `i` are `2i + 1` and `2i + 2`,
and `items[0]` is the request that `is_request_before` (4.1.1) places first.
4.3 adds push, peek and pop.

**Function.** `int init_heap(t_heap *heap, int capacity)` in
`coders/src/heap/init_heap.c`: allocates an array of `capacity` requests and
sets `size = 0`, `capacity = capacity`. Returns 0 on success, -1 if `heap` is
NULL, `capacity < 1`, the byte size would overflow, or `malloc` fails; on -1
`*heap` is left untouched (`docs/conventions.md`: the out-parameter is not
written on failure).

**Ownership.** The caller owns the array once `init_heap` returned 0 and
releases it with `free_heap` (4.2.2). Precondition: a non-NULL `heap` points
to writable `t_heap` storage that owns no live allocation. No previous field
value is read, so prior initialization is not required (AC1 sentinel case);
calling `init_heap` on a live heap would leak its array, and the function
cannot detect it. The initial contents of the allocated slots are unspecified;
each slot must be written before it is read (4.3 only reads slots below
`size`).

**Capacity 2 per dongle (phase 05).** A dongle heap only ever holds the
requests of its two neighbours (PLAN.md "Acquisition"). Each coder has at most
one queued entry per distinct dongle; retries never enqueue duplicates. With
N = 1, the sole dongle receives at most one entry, never two copies of the
same request; the coder cannot compile.

Pure core (PLAN.md layers: `malloc`/`free` allowed, no pthread, clock or
output). Close-time documentation: `docs/architecture.md` gains the `heap/`
row.

**README.** No close-time update (no user-visible change until phase 09).
