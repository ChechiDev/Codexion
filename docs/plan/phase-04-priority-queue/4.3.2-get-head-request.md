## Description

`int get_head_request(const t_heap *heap, t_request *out)` in
`coders/src/heap/get_head_request.c`: copies the head of the min-heap
(`items[0]`, the request served first) into `*out` without removing it.

The arbiter (phase 06) needs it to apply the PLAN.md "head of both" rule: a
coder may take its dongles only when its request is the head of both dongle
heaps, which it checks by peeking both heads and comparing them with its own
request by `ticket` (unique per logical request and identical in both heaps,
4.1.1; `coder` is not needed), before popping anything. The arbiter checks
both return values, both heads, availability and cooldown, and pops both
entries while holding both dongle mutexes.

**Return contract (follows `docs/conventions.md`).** 0 on success; -1 if
`heap` or `out` is NULL or the heap is empty (`size == 0`). On -1 `*out` is
not written and the heap is never modified.

**Preconditions.** A non-NULL `heap` was initialised by `init_heap` and not
freed, and its slots `[0, size)` were written by `push_request` (or the test).
A non-NULL `out` points to writable `t_request` storage that overlaps neither
`*heap` nor its backing array. No locking: the caller holds the dongle mutex.

Pure core (PLAN.md layers). Close-time documentation: the `heap/` row of
`docs/architecture.md` mentions it.

**README.** No close-time update (no user-visible change until phase 09).
