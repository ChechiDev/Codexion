## Description

`void print_run_error(void)` in `coders/src/cli/print_run_error.c`: the one
message `main` prints when a valid run ends with an internal error (9.5.2):
`Error: simulation failed`. It lives in `cli/`, which owns every user-facing
message (PLAN.md layers), so `lifecycle/` stays silent.

**Why a fixed message.** The causes (a mutex, clock, `write` or
`pthread_create` failure inside a thread) are internal and not actionable by
the user; the simulation log already shows how far the run got. A specific
cause would need error codes through every layer for no user benefit. The
message is on stderr, so it never mixes with the simulation log on stdout.

**Still visible when stdout fails.** If stdout is broken
(for example redirected to `/dev/full`), stderr usually still works, so the
user still sees why the exit status is non-zero.

**Name.** `print_` + what is printed, like `print_usage` and
`print_arg_error`. Checked: no `print_run_error` exists in `tests/` or
`coders/`.

**README.** Updated with 9.5.2 (exit statuses and this message).
