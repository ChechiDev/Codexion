## Description

`main` (`coders/main.c`) today validates the arguments and returns 0 without
running anything. This subtask wires the whole program: after validation it
runs one simulation with `run_simulation` (9.4.1) on a `t_sim` that lives on
`main`'s own stack, and turns its result into the exit status.

**Exit statuses.**
- 0: the simulation ran and ended normally: every coder reached the compile
  target, or one coder burned out (both are the ends the subject describes),
  or zero compiles were required (nothing to do).
- 1 (`EXIT_USAGE`, unchanged): wrong argument count or an invalid argument;
  error lines and usage on stderr, nothing started.
- 2 (`EXIT_RUNTIME`, new): a valid run hit an internal error (a mutex,
  clock, `write` or thread-creation failure); `Error: simulation failed` on
  stderr (9.5.1).

**Why the storage is in `main`.** On the unrecoverable paths of 9.4.1 a
thread may still use the simulation, so its storage must stay valid until the
process ends. `main` returns right after printing the error, which ends the
process (and every thread), so a `t_sim` on `main`'s stack is valid exactly as
long as needed. It also keeps the program free of globals.

**README.** Updated by Codex at close (AGENTS.md "living files"), not by the

section on exit statuses (0 for a normal end, target met or burnout; 1 for
invalid arguments; 2 for an internal error, with the `Error: simulation
