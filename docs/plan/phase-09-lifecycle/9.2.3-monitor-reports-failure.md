## Description

`void *run_monitor(void *arg)` (8.2.1) groups "target met" and every failure
under one exit (`LEAVE_STOP`: `set_stopped` + `wake_dongles`), so the
lifecycle cannot tell a clean end from an internal error. Phase 09 adds
`failed` (9.1.1, 9.1.2) so `main` can exit non-zero on a runtime error (user
decision 2026-11-06).

**Contract change.**
- Target met (0 required included) and a logged burnout stay **normal ends**:
  `failed` is not touched unless stopping or waking itself fails.
- A failed check, a failed `usleep`, or a burnout line that could not be
  written or was refused, is an **error**: `set_failed`, `set_stopped`,
  `wake_dongles`, each tried even if the previous one failed. Marking first
  keeps the error recorded even if someone else stops the run meanwhile.
- Stopped by someone else: unchanged, silent, `failed` untouched (the thread
  that stopped the run reports its own failure).
- Scan order, ~1 ms cadence, 10 ms burnout latency, tie-break helper and lock
  discipline are unchanged; the sealed 8.2.1 oracle is the regression check.

**Why `print_burnout` -1 is an error.** It returns -1 for "already stopped"
and for lock or write failures alike (3.4.4). In the lifecycle the first case
only happens after another thread failed and marked `failed`, so treating
every -1 as an error is correct and at worst redundant, without changing the
sealed `print_burnout` contract.

**Name.** No new public identifier (a new exit constant such as `LEAVE_ERROR`
is a local `#define` in the file).

**README.** No update (the exit status is documented with 9.5.2).
