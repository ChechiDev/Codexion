## Description

`int take_coder_dongles(t_coder *coder, int *taken)` (7.2.1) takes the
coder's dongles and logs `has taken a dongle` once per dongle. Today, when a
log line fails, its helper flattens the `print_state` result to -1 and
`release_taken` re-reads `is_stopped` to guess why: stopped → normal "not
taken", running → failure. A real `write` error that coincides with a stop is
therefore reported as a normal end and lost.

Issue #34 made `print_state` return 1 on a stop and -1 only on a real
failure, so the cause no longer needs guessing. This subtask keeps it:

- `print_state` 1 (stopped): release once, return 0 with `taken == 0`.
- `print_state` -1 (failure): release once, return -1, even if the run is
  stopped by then.
- a failed release: -1.

It is the first half of the old 9.2.1 (split at the phase gate so each
subtask is one atomic unit); `run_coder` uses this result in 9.2.2 to mark
`failed` only on a real error.
