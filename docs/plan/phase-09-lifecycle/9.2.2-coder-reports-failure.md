## Description

`void *run_coder(void *arg)` (7.3.1) today sends every non-zero helper result
to its failure exit (`set_failure`: release, `set_stopped`, `wake_dongles`).
Phase 09 adds
`failed` (9.1.1, 9.1.2) so `main` can exit non-zero on a runtime error (user
decision 2026-11-06). Issues #32 and #34 made `sleep_ms` and `print_state`
return 1 on a stop and -1 only on a real failure, and 9.2.1 made
`take_coder_dongles` keep that cause, so the coder can now classify every
result instead of guessing it afterwards.

**Contract change.**
- Normal end (result 1, or `take_coder_dongles` returning 0 with `taken ==
  0`): release any held dongle once, return NULL. `failed` is not touched
  unless that release fails.
- Failure (any -1): `set_failed`, release any held dongle once, `set_stopped`,
  `wake_dongles`, return NULL. Marking first keeps the error recorded even if
  another thread stops the run meanwhile (9.1.2).
- Everything else (cycle order, logs, `compile_count` only after a full
  compile, single-coder hold-and-wait) is unchanged; the sealed 7.3.1 oracle
  is the regression check.

**Release on a normal end can fail.** `release_dongles` reads the clock and
locks, broadcasts and unlocks the dongle mutexes even when the run is
stopped; any of those can fail. The coder tries it once and treats a -1 as a
failure; the ACs promise free dongles and unlocked mutexes only on the healthy
paths they exercise.

**Name.** No new public identifier.

**README.** No update (the exit status is documented with 9.5.2).
