Test notes for the oracle: every worker is created with `pthread_create` returning 0; readiness, the gate, the caller's "returned" flag and result are read and written under a test mutex; a watchdog (`alarm`, a few seconds, wider under valgrind/TSan) turns a hang into a failure; `free_sim` is called only after every created thread (workers and the caller thread) was joined. A failing join cannot be forced without undefined behaviour (a self-join is undefined in POSIX; glibc's `EDEADLK` is not portable and breaks under TSan), so "every join is attempted even after one failed" is code review. ## Description

`int join_threads(t_sim *sim, int coders)` in
`coders/src/lifecycle/join_threads.c`: waits for the first `coders` coder
threads and then for the monitor thread of the simulation. It is the single
join path for both the normal end (9.4.1 calls it with `number_of_coders`)
and a failed start (9.3.2 calls it with the number of coder threads created
before the failure).

**Preconditions.** `sim` was built by `init_simulation` and stays valid and
unchanged during the call; the monitor thread and the first `coders` coder
threads were created successfully, are joinable, distinct, not yet joined or
detached by anyone, and are joined by nobody else; the caller is none of
those threads and holds no mutex they need to finish; the caller has already
arranged that every target thread will end (normal end of the run, or 9.3.2's
stop and wake on a failed start). No `pthread_t` value can mark "no thread"
portably (9.1.1), so `join_threads` cannot tell whether `sim->monitor` holds a
thread: the caller guarantees it (9.3.2 never calls `join_threads` when the
monitor creation failed).

**Try every join.** A failed `pthread_join` (`EDEADLK`, `EINVAL`, `ESRCH`, all
programming errors) does not stop the others: leaving a thread unjoined
would let it keep running while the caller frees the simulation. Try-all
reduces the damage of such a programming error but does not prove that every
thread ended.

**Contract for the callers (future, recorded here).** After a -1, the
simulation must not be freed, reused, read without a lock (`failed`), nor
joined again (some joins already succeeded), and its storage must stay valid
until the process ends: 9.4.1 must not let a local `t_sim` expire while a
thread might still use it, and must propagate the error to `main` at once.
9.3.2 must pass on a failure of its recovery join in the same way. This path
is treated as an unrecoverable programming error, not a normal outcome.

**Order.** Coders in index order, then the monitor. It is not needed for
correctness (while the caller waits on the coders, the monitor keeps running
and can stop and wake the run; the error exits of 9.2.2 and 9.2.3 keep that
responsibility); it is fixed so the behaviour is predictable and reviewable.

**Module.** New `lifecycle/` module (orchestration): `join_threads` here,
`start_threads` in 9.3.2, `run_simulation` in 9.4.1; `main` (9.5.2) stays the
interface. Names come from the `start_` / `join_` row of
`docs/conventions.md`. Close-time documentation: a `lifecycle/` row in
`docs/architecture.md` and the modules list of PLAN.md's architecture
overview, kept consistent with the phase 09 task layers.
