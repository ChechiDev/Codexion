## Description

Data-only step of task 9.1. Phase 09 needs to tell a normal end of the run
(burnout logged, or every coder reached the compile target) from an internal
error (mutex, clock, `write` or `usleep` failure inside a thread) so that
`main` can exit non-zero on the latter (user decision 2026-11-06). The
`stopped` flag cannot carry that: both kinds of end set it. This subtask only
adds the storage and clears it; nothing reads or sets it yet.

**Future synchronisation contract (not implemented here).** `init_simulation`
writes `failed` before any thread exists, so no lock is needed there. While
threads run, `failed` will be written only through `set_failed` (9.1.2) under
`stop_mutex`. `run_simulation` (9.4.1) will read it without a lock only after
**successful** joins of every thread that was created (`pthread_join` gives the
memory synchronisation); after a failed join it must not read it unlocked.

`t_sim` also has no place for the monitor thread handle today (coders keep
theirs in `t_coder.thread`). `pthread_t monitor` gives 9.3 a home for it, so
`start_threads` and `join_threads` share it through the simulation instead of
an extra parameter (Norm: at most 4 parameters). It is meaningful only after a
successful `pthread_create`; 9.3 tracks that, not a sentinel value.

**Contract change.** With valid arguments, `init_simulation` (5.4.2) also
clears `failed`. Nothing else changes: same return values, same
partial-failure cleanup, `monitor` left untouched.

**Standalone.** Kept separate from `set_failed` (9.1.2): merging them would
need four files (`main.h`, `init_simulation.c`, the new source and the
`Makefile`), above the 1-3 limit.

**Name.** `failed` and `monitor` are struct members. Checked: no member with
either name exists in `t_sim` or `t_coder`; the `failed` fields in
`tests/acceptance/test_6.1.1.c` and `test_6.1.2.c` belong to test-local
structs, and `run_monitor` is a function (no clash). Tests may pass
uninitialised `t_sim` storage (for example `t_sim sim;` in
`tests/acceptance/test_5.4.2.c`), so every member that is read must be
initialised explicitly: `failed` by `init_simulation`, `monitor` by
`pthread_create` before any use.
