## Description

`int free_coders(t_coder *coders, int count)` in
`coders/src/cleanup/free_coders.c`: tears down the first `count` coders of a
`malloc`'d array with `destroy_coder` (5.3.2), last first, then frees the
array itself. The counterpart of `free_dongles` (5.2.3) for coders.

**Count = successfully initialised elements.** `count` is the number of
leading elements that `init_coder` initialised with success, not the array
length. It is the single teardown path: `init_coders` (5.3.4) calls it with
`k` when element `k` fails (including `k = 0` right after the `malloc`), and
`free_sim` (5.4.2) calls it with `n`. Elements at index `>= count` are never
read.

**Return contract.** 0 on success. -1 on invalid input (`count < 0`, or
`coders == NULL` with `count > 0`), in which case nothing is touched or freed;
also -1 if any `destroy_coder` failed, but the teardown still completes (every
element destroyed, array freed) so nothing leaks. `free_coders(NULL, 0)` is a
valid no-op.

**Ownership.** After any call with valid input the array is freed: the caller
must not use the pointer again and should reset it (`free_sim` sets
`sim->coders = NULL`). Precondition: the same as `destroy_coder` for each of
the `count` elements (unlocked mutex, every thread joined, phase 09). The
shared `sim` the coders point to is not touched.

Adapter (PLAN.md layers: `init`/`cleanup` own the mutex/cond/alloc lifecycle).
Close-time documentation: the `cleanup/` row of `docs/architecture.md` mentions
it.
