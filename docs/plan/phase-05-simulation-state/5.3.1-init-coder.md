## Description

**Type.** `main.h` gains, in the Types section after `t_dongle`:

    typedef struct s_coder
    {
        int              id;                  /* seat + 1, printed in the logs */
        int              first_dongle;        /* lower dongle index */
        int              second_dongle;       /* higher index; equal if n == 1 */
        pthread_mutex_t  mutex;               /* guards the two fields below */
        long             last_compile_start;  /* ms since start, 0 before the first */
        int              compile_count;       /* compiles done */
        pthread_t        thread;              /* set by phase 09 only */
        struct s_sim     *sim;                /* back pointer for the routine */
    }   t_coder;

One coder of the circle (subject: one thread per coder; PLAN.md "Coder
thread": a per-coder mutex guards `last_compile_start` and `compile_count`,
read by the monitor). The field is `struct s_sim *` rather than `t_sim *` so
that 5.4.1 can move `t_sim` after `t_coder` (it will hold the coders array)
without touching this type.

**Function.** `int init_coder(t_coder *coder, t_sim *sim, int seat, int n)` in
`coders/src/init/init_coder.c`: computes the seat's ordered dongle pair with
`get_dongle_pair` (5.1.1), initialises the coder mutex, then sets `id = seat +
1`, the two dongle indices, `last_compile_start = 0` (the edf time base of
4.1.2: ms since the simulation start, 0 before the first compile),
`compile_count = 0` and the `sim` back pointer (`pthread_create` passes a
single argument, the coder; phase 07 reaches the shared state through it).

**`thread`.** Declared now so the type is complete, but phase 05 never reads,
writes, joins or tears it down; phase 09 sets it with `pthread_create`.

**Return contract.** 0 on success; -1 if `coder` or `sim` is NULL, `n < 1`,
`seat` is outside `[0, n)`, or `pthread_mutex_init` fails. Validation happens
before the mutex init, so on invalid input `*coder` is untouched; on a mutex
init failure nothing is live (there is nothing else to roll back). The caller
never calls `destroy_coder` (5.3.2) after a -1.

**Ownership.** On 0 the caller owns the mutex and releases it with
`destroy_coder` (5.3.2). `sim` is borrowed, never dereferenced here.
Precondition: `coder` owns no live mutex (no previous field is read).

Adapter (PLAN.md layers: `init`/`cleanup` own the mutex/cond/alloc lifecycle).
Close-time documentation: the `init/` row of `docs/architecture.md` mentions it.

**README.** No close-time update (no user-visible change until phase 09).
