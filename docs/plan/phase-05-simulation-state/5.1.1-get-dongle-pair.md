## Description

`int get_dongle_pair(int seat, int n, int *first, int *second)` in
`coders/src/init/get_dongle_pair.c`: the seat-to-dongle mapping of the circle
(subject: N coders and N dongles around a table, each coder between two
dongles; PLAN.md "Concurrency design").

**Indexing.** `seat` is 0-based (`0 <= seat < n`) and indexes both
`sim->coders` and `sim->dongles` (5.4). The coder id printed in the logs is
`seat + 1` (set by `init_coder`, 5.3.1). Seat `i` sits between dongle `i`
and dongle `i + 1`, wrapping to dongle 0 for the last seat, computed without
`seat + 1` overflowing at `INT_MAX`.

**Order.** The two indices are returned lower first (`first < second`), so
phase 06 locks the two dongle mutexes in this order (PLAN.md "Acquisition":
lower index first, so the check-and-take section cannot deadlock). The field
names in `t_coder` (5.3.1) are `first_dongle` and `second_dongle` for the same
reason: they are ordered indices, not left and right.

**One coder.** With `n == 1` both outputs are 0: one resource. Phase 06 must
detect `first == second` and lock and push it only once (phase 04 invariant:
one coder = one dongle, no double lock or push). This is the only case where
the two indices are equal.

**Return contract.** 0 on success; -1 if `first` or `second` is NULL,
`n < 1`, or `seat` is outside `[0, n)`. On -1 neither output is written
(`docs/conventions.md`).

Pure core (PLAN.md layers: no pthread, clock, output or allocation). It lives
in `src/init/` because its only caller is the init code (5.3.1); being pure, it
is unit-testable without threads. Close-time documentation:
`docs/architecture.md` gains the `init/` row.
