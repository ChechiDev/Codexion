## Description

`int destroy_coder(t_coder *coder)` in `coders/src/cleanup/destroy_coder.c`:
releases what `init_coder` (5.3.1) created, which is only the coder mutex.
The other fields are plain values and the `sim` back pointer is borrowed, so
nothing else is freed.

**Precondition.** `coder` was fully initialised by `init_coder` (returned 0)
and not destroyed since; its mutex is unlocked and no thread will touch it
again (in the simulation: every coder and the monitor have been joined, phase
09). A coder whose init failed is never passed here (5.3.1 leaves nothing
live). Calling it twice is undefined behaviour (POSIX: destroying a destroyed
mutex). It never joins `thread`: joining belongs to phase 09, before teardown.

**Return contract.** 0 if `pthread_mutex_destroy` succeeded; -1 if `coder` is
NULL or the destroy failed. No field is reset; a later `init_coder` overwrites
them.

Adapter (PLAN.md layers: `init`/`cleanup` own the mutex/cond/alloc lifecycle).
Close-time documentation: the `cleanup/` row of `docs/architecture.md` mentions
it.

**README.** No close-time update (no user-visible change until phase 09).
