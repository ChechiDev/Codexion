## Description

`int init_coders(t_coder **out, t_sim *sim, int n)` in
`coders/src/init/init_coders.c`: allocates the array of the `n` coders of the
circle and initialises each with `init_coder(&array[i], sim, i, n)` (5.3.1),
seat 0 first, so element `i` is seat `i`, coder id `i + 1`, sitting between
dongles `i` and the next one (`get_dongle_pair`, 5.1.1). The counterpart of
`init_dongles` (5.2.4) for coders.

**Rollback.** If element `i` fails, `init_coder` has left nothing live for it,
so `init_coders` hands the `i` live elements and the array to
`free_coders(array, i)` (5.3.3) and returns -1. Nothing stays allocated or
initialised after a failure.

**Return contract.** 0 on success, with `*out` pointing to the array. -1 if
`out` or `sim` is NULL, `n < 1`, the byte size would overflow `size_t`,
`malloc` fails, or any element fails; on -1 `*out` is not written.

**Ownership.** On 0 the caller owns the array and every coder mutex and
releases them with `free_coders(*out, n)` (5.3.3), after every thread has been
joined (phase 09). `sim` is borrowed and only stored in each coder. `n` comes
from `t_config.number_of_coders` (validated `>= 1`, no upper cap); a huge `n`
fails at `malloc`.

Adapter (PLAN.md layers: `init`/`cleanup` own the mutex/cond/alloc lifecycle).
Close-time documentation: the `init/` row of `docs/architecture.md` mentions it.

**README.** No close-time update (no user-visible change until phase 09).
