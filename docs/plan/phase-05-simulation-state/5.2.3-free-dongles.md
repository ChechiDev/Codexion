## Description

`int free_dongles(t_dongle *dongles, int count)` in
`coders/src/cleanup/free_dongles.c`: tears down the first `count` dongles of a
`malloc`'d array with `destroy_dongle` (5.2.2), last first, then frees the
array itself.

**Count = successfully initialised elements.** `count` is the number of
leading elements that `init_dongle` initialised with success, not the array
length. This is what makes it the single rollback path: `init_dongles` (5.2.4)
calls it with `k` when element `k` fails (elements `0..k-1` are live, `k`
rolled itself back), including `k = 0` right after the `malloc`; full teardown
(`free_sim`, 5.4.2) calls it with `n`. Elements at index `>= count` are never
read.

**Return contract.** 0 on success. -1 on invalid input (`count < 0`, or
`dongles == NULL` with `count > 0`), in which case nothing is touched or freed;
also -1 if any `destroy_dongle` failed, but then the teardown still completes
(every element destroyed, array freed) so nothing leaks. `free_dongles(NULL, 0)`
is a valid no-op.

**Ownership.** After any call with valid input the array is freed: the caller
must not use the pointer again and should reset it (`free_sim` sets
`sim->dongles = NULL`). Precondition: the same as `destroy_dongle` for each of
the `count` elements (unlocked, no waiter, threads joined).

Adapter (PLAN.md layers: `init`/`cleanup` own the mutex/cond/alloc lifecycle).
Close-time documentation: the `cleanup/` row of `docs/architecture.md` mentions
it.
