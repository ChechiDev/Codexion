## Description

**Type.** `main.h` gains, in the Types section after `t_heap`:

    typedef struct s_dongle
    {
        pthread_mutex_t  mutex;        /* guards heap, available, released_at */
        pthread_cond_t   cond;         /* waiters for this dongle (phase 06) */
        t_heap           heap;         /* requests of its two neighbours */
        int              available;    /* 1 free, 0 taken */
        long             released_at;  /* ms since start of the last release, -1 never */
    }   t_dongle;

One dongle of the circle (subject: each dongle is protected by a mutex; a
condition variable may manage the waiting queue; PLAN.md "Dongle": mutex, cond,
own request heap, `available`, `released_at` for the cooldown).

**Function.** `int init_dongle(t_dongle *dongle)` in
`coders/src/init/init_dongle.c`: initialises the mutex, then the cond, then a
request heap of capacity 2 (4.2.1: a dongle heap only ever holds the requests
of its two neighbours; with one coder, its single request), and sets
`available = 1`, `released_at = -1`.

**Never released.** `released_at = -1` means the dongle has not been released
yet, so no cooldown applies before its first take (Codex advisory review of the
phase 05 tasks: a 0 would impose a cooldown from the simulation start). Phase 06
treats -1 as "cooldown elapsed". Real values are milliseconds elapsed since the
simulation start (`>= 0`), the same time base as the edf key (4.1.2).

**Failure and rollback.** Returns 0 on success, -1 if `dongle` is NULL or any
of the three steps fails. On failure it destroys exactly what it had already
initialised, in reverse order, so nothing live is left: the caller must not
call `destroy_dongle` (5.2.2) on it. The contents of `*dongle` after -1 are
unspecified (the pthread init calls may have written into it), but it owns no
resource.

**Ownership.** On 0 the caller owns the mutex, the cond and the heap array and
releases them with `destroy_dongle` (5.2.2), only on a fully initialised
dongle. Precondition: `dongle` points to writable storage that owns no live
resource; no previous field is read, so prior zeroing is not required (AC1
sentinel case).

Adapter (PLAN.md layers: `init`/`cleanup` own the mutex/cond/alloc lifecycle).
Close-time documentation: the `init/` row of `docs/architecture.md` mentions it.
