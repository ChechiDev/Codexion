## Description

`int is_dongle_ready(const t_dongle *dongle, int coder, long now, int cooldown)`
in `coders/src/policy/is_dongle_ready.c`: the per-dongle half of the take rule
(PLAN.md "Acquisition": a coder takes its dongles only when it is the head of
both heaps and both are available with their cooldown elapsed). 6.3.4 calls it
for both dongles and 6.3.5 for the single one, inside their critical section.

**Rule.** 1 when all three hold: the heap head's `coder` equals `coder` (the
1-based coder id of 5.3.1), `available == 1`, and the cooldown has elapsed
(`released_at == -1`, "never released" from 5.2.1, or `now - released_at >=
cooldown`, subject: a released dongle cannot be taken again until
`dongle_cooldown` ms have passed). Otherwise 0.

**Time base.** `now` and `released_at` are ms elapsed since the simulation
start (`get_elapsed_ms(sim->start_ms)`, the same base as `last_compile_start`
and the edf key); the caller reads the clock and passes `now`, so this function
stays pure and deterministic to test.

**Locking.** None inside: the caller holds the dongle's mutex, which guards
`available`, `released_at` and the heap. The function only reads them.

**Return contract.** `is_` question: exactly 0 or 1; any invalid input
answers 0 ("not ready"), which is the safe answer for the caller.

Pure core (PLAN.md layers: `policy` holds the arbitration rules; no pthread
call, clock or output). Checked: no `is_dongle_ready` helper exists in
`tests/`. Close-time documentation: the `policy/` row of
`docs/architecture.md` mentions the readiness rule.
