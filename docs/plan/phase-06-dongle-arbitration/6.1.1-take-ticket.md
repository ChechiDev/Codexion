## Description

`int take_ticket(t_sim *sim, long *out)` in `coders/src/state/take_ticket.c`:
hands out the arrival ticket of one request. Every request a coder queues
(6.1.2) carries one ticket, used as the `fifo` key and as the tie-breaker of
the `edf` key (PLAN.md "Arbitration keys"; phase 04 invariant: one
simulation-wide, synchronized, strictly increasing ticket per logical request,
no overflow).

**Contract.** Under `sim->ticket_mutex` (5.4.2 initialises it, `next_ticket`
starts at 0): if `0 <= next_ticket < LONG_MAX`, the current value is the
ticket and `next_ticket` is incremented; otherwise the tickets are exhausted
(or the field is corrupted) and the call fails. Returns 0 and writes `*out`
only on full success; -1 on NULL input, exhausted or negative counter, or a
lock/unlock failure, with `*out` untouched. `LONG_MAX` itself is never handed
out, so the increment cannot overflow.

**Lock order.** `ticket_mutex` is a leaf: nothing else is locked while it is
held, and the caller must not hold a dongle mutex when calling it (6.1.2
builds the request before any dongle is locked; PLAN.md "Acquisition").

**Name.** The verb `take_` is "acquires a shared resource"
(`docs/conventions.md`): the ticket counter is shared by every coder and the
call consumes one value. Checked: no `take_ticket` helper exists in `tests/`.

Adapter (PLAN.md layers: uses a pthread mutex, no clock or output). It lives in
`src/state/` next to `is_stopped` / `set_stopped`: the counter is part of the
simulation-wide state. Close-time documentation: the `state/` row of
`docs/architecture.md` mentions the ticket counter.

**README.** No close-time update (no user-visible change until phase 09).
