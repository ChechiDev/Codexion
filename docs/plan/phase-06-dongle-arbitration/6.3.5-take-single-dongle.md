## Description

`int take_single_dongle(t_coder *coder, int *taken)` in
`coders/src/dongle/take_single_dongle.c`: acquisition when there is one coder
and therefore one dongle (subject: "if there is only one coder, there must be
only one dongle on the table"; 5.1.1 maps both indices to 0).

**Why a separate function.** `take_dongles` (6.3.4) needs two distinct
dongles and rejects `first_dongle == second_dongle`. Phase 07's sealed goal
says the lone coder *takes* its only dongle and waits to burn out, so the
dongle state (heap, `available`, cooldown) must still be handled by the arbiter
module, with the same rules: queue a request, take only as head, available and
after the cooldown, wait with a timed cond wait, leave on stop.

**Sequence.** Same as 6.3.4 with one mutex: build the request, lock, push
once, then loop: stopped → leave with `*taken = 0`; ready → pop, take, leave
with `*taken = 1`; else a 1 ms timed wait on the dongle's cond (here the
waiter holds only this mutex, so it waits on it directly without
`wait_for_dongles`). The stop check and the wait happen under the same mutex,
so `wake_dongles` cannot be missed.

**Fatal path.** As in 6.3.4: once the request is queued, any failure unlocks,
calls `set_stopped` and `wake_dongles` and returns -1.

**Return contract.** 0 with `*taken = 1` (dongle held, mutex released) or
`*taken = 0` (stopped, nothing held); -1 on invalid input or failure, with
`*taken` untouched and no mutex held. Logging "has taken a dongle" once and
waiting for the burnout without compiling is phase 07's job; releasing uses
`release_dongles` (6.3.3), which handles the single dongle.

**Stop check errors.** `is_stopped` (3.2.1) answers 1 when it cannot lock `stop_mutex` (its justified exception), so a `stop_mutex` failure is handled as a stop: the call returns 0 with `*taken = 0`, not -1, and the thread leaves as on a real stop. Its request may stay queued; the run still ends (the monitor of phase 08 detects the resulting burnout), it cannot hang.

**Name.** `take_` acquires a shared resource (`docs/conventions.md`). Checked:
no `take_single_dongle` helper exists in `tests/`.

Orchestration (PLAN.md layers: `dongle` module). Close-time documentation: the
`dongle/` row of `docs/architecture.md` mentions the one-coder case.
