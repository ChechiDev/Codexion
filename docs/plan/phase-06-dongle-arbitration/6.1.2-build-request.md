## Description

`int build_request(t_coder *coder, t_request *out)` in
`coders/src/dongle/build_request.c`: builds the request a coder queues in its
dongle heaps (6.3.4, 6.3.5): `coder = coder->id`, `ticket` from `take_ticket`
(6.1.1), `key` from the configured policy (PLAN.md "Arbitration keys":
`fifo` = ticket; `edf` = `last_compile_start + time_to_burnout`, ties broken by
the ticket through `is_request_before`, 4.1.1).

**Sequence.** 1) Validate the pointers. 2) Lock the coder's mutex, copy
`last_compile_start`, unlock (phase 07 writes it under the same mutex, so the
edf deadline is never torn). 3) `take_ticket`. 4) `get_request_key`; a -1 key
is checked here, before anything is queued (phase 04 invariant). 5) Write
`*out`.

**Return contract.** 0 on success; -1 on NULL input, a lock/unlock failure,
exhausted tickets or an invalid key, with `*out` untouched. A failure after
step 3 may consume a ticket: tickets must be strictly increasing, not
contiguous, so a gap is harmless.

**Lock order.** Coder mutex, then (after releasing it) `ticket_mutex`; both are
leaves and the caller must not hold any dongle mutex (6.3.4 builds the request
before locking its dongles). The edf time base is the simulation clock (ms
since `start_ms`), the same as `last_compile_start`.

**Name and module.** `build_` is "builds a structure"
(`docs/conventions.md`). Checked: no `build_request` helper exists in
`tests/`. First file of `src/dongle/`, the orchestration module of PLAN.md
(it combines core policy with the `take_ticket` adapter). Close-time
documentation: `docs/architecture.md` gains the `dongle/` row.

**README.** No close-time update (no user-visible change until phase 09).
