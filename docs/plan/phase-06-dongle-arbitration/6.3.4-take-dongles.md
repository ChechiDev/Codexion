## Description

`int take_dongles(t_coder *coder, int *taken)` in
`coders/src/dongle/take_dongles.c`: the two-dongle acquisition of PLAN.md
"Acquisition: both dongles at once (no hold-and-wait)".

**Sequence.**
1. Validate; build the request `(key, ticket, coder)` with `build_request`
   while holding no dongle mutex.
2. Lock `first_dongle`, then `second_dongle` (lower index first), push the
   same request into both heaps (phase 04 invariant: same request in both
   heaps, under both mutexes).
3. Loop holding both mutexes:
   - stopped → unlock, `*taken = 0`, return 0 (the thread holds nothing and
     leaves; its request stays queued, harmless because every thread exits and
     `free_sim` frees the heaps);
   - both dongles ready for this coder (head of both heaps, available,
     cooldown elapsed on the simulation clock) → pop itself from both heaps,
     mark both unavailable, unlock, `*taken = 1`, return 0 (check and take in
     one critical section);
   - else `wait_for_dongles`: a bounded wait on the first dongle's cond
     (1 ms slice), returning with both mutexes held.

**Why it is safe.** A coder never holds one dongle while waiting for the other
(Coffman's hold-and-wait is broken); the two mutexes are always locked lower
index first (no circular wait in the check-and-take section); the stop is
checked while holding the first mutex up to the cond wait, so the
`set_stopped` + `wake_dongles` wake-up cannot be lost (6.3.1). By the PLAN.md
progress argument, the waiter with the smallest `(key, ticket)` heads both its
heaps and is served within `C + D` plus the wait latency.

**Fatal path.** A failure once the request is queued cannot be undone (the heap
has no remove-by-coder operation) and would leave a stale head blocking a
neighbour, so the function releases every mutex it still holds, stops the
simulation (`set_stopped`) and wakes every waiter (`wake_dongles`), then
returns -1: the run ends cleanly (PLAN.md: pthread failures shut down
cleanly). A failure before anything is queued just unlocks and returns -1.

**Return contract.** 0 with `*taken = 1` (both dongles held, mutexes released)
or `*taken = 0` (stopped, nothing held); -1 on invalid input or failure, with
`*taken` untouched and no mutex held. A stop set after the last readiness check
does not undo the take: the caller (phase 07) sees the stop at its next log and
releases. Logging "has taken a dongle" (twice) is the caller's job, after this
returns (phase 07), never under a dongle mutex.

**Stop check errors.** `is_stopped` (3.2.1) answers 1 when it cannot lock `stop_mutex` (its justified exception), so a `stop_mutex` failure is handled as a stop: the call returns 0 with `*taken = 0`, not -1, and the thread leaves as on a real stop. Its request may stay queued; the run still ends (the monitor of phase 08 detects the resulting burnout), it cannot hang.

**Name.** `take_` acquires a shared resource (`docs/conventions.md`, example
`take_dongles`). Checked: no `take_dongles` helper exists in `tests/`.

Orchestration (PLAN.md layers: `dongle` module). Close-time documentation: the
`dongle/` row of `docs/architecture.md` describes the acquisition protocol.

**README.** No close-time update (no user-visible change until phase 09; the
"Blocking cases handled" README section is written in phase 10).
