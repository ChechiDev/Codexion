## Description

`int get_deadline(long ms, struct timespec *out)` in
`coders/src/time/get_deadline.c`: the absolute time `ms` milliseconds from now,
in the form `pthread_cond_timedwait` takes. 6.3.2 uses it to bound every wait
on a dongle cond (PLAN.md "Dongle": waits use `pthread_cond_timedwait`, no
busy-wait).

**Time base.** This is the only function of the phase working in absolute
wall-clock time: `pthread_cond_timedwait` compares its deadline with
`CLOCK_REALTIME`, which `gettimeofday` reads (both allowed by the subject).
Everything else in the arbiter (`released_at`, `now`, edf keys) uses ms elapsed
since `start_ms`.

**Return contract.** 0 with `*out` set and normalised (`tv_nsec` in
`[0, 1e9)`); -1 on `out` NULL, `ms < 0`, a clock failure or a deadline whose
seconds would overflow, with `*out` untouched.

**Name.** `get_` computes a value without changing anything
(`docs/conventions.md`). Checked: no `get_deadline` helper exists in `tests/`.

Adapter (PLAN.md layers: `time` reads the clock). Close-time documentation: the
`time/` row of `docs/architecture.md` mentions the deadline helper.

**README.** No close-time update (no user-visible change until phase 09).
