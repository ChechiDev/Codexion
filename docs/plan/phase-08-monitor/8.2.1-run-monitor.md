## Description

`void *run_monitor(void *arg)` in `coders/src/monitor/run_monitor.c`: the
body of the monitor thread (`arg` is the `t_sim *`). Subject: a separate
monitor thread detects a burnout precisely and stops the simulation; the
burnout line is printed within 10 ms of the real burnout; the run also ends
when every coder compiled `number_of_compiles_required` times. PLAN.md
"Monitor thread": scans about every 1 ms; on burnout logs, sets stop and
broadcasts every dongle cond; also detects the compile target.

**Contract.** Loop until it leaves; each scan follows the order of the Code
review check:

- **Stopped by someone else** (a coder failure, 7.3.1 exit policy): checked
  first; leave without a line.
- **Target met** (`get_target_met`, 8.1.2), 0 required included (PLAN.md
  "Edge cases": ends immediately and cleanly): checked **before** the burnout
  scan, so when both are observed in the same pass the run ends cleanly
  without a burnout line. User decision 2026-11-05 after a Codex advisory
  (`progress/advisory_8.2.1_ac6.md`): subject line 137, "if every coder
  compiled at least this number of times the simulation stops; otherwise it
  stops when someone burns out". The monitor cannot tell which event happened
  first; this order is the policy for a joint observation.
- **Burnout** (`get_burned_out`, 8.1.1, `>=` deadline): printed at once
  through `print_burnout`, which makes the first stop and writes the line in
  one critical section under `log_mutex` (3.4.4), so no other line can follow
  it. If a coder already stopped the run, `print_burnout` returns -1 and
  prints nothing; the monitor still wakes and leaves.
- **Wake-up:** every exit where the monitor ends the run (target, burnout,
  failure) calls `wake_dongles` (6.x) so no coder stays blocked on a dongle
  cond. When someone else stopped the run, that thread wakes the waiters
  (`run_coder` exit policy) and the monitor just leaves.
- **Burnout line failed:** a -1 from `print_burnout` may come before the stop
  was made (a `log_mutex` lock failure), so the monitor then calls
  `set_stopped` (idempotent) and `wake_dongles`, so no coder is left running
  without a monitor.
- **Failure:** a -1 from a check sets stop and wakes every waiter (same exit
  policy as `run_coder`), each step tried even if the previous failed, then
  leaves. Lifecycle error reporting (failure vs normal end) is phase 09.

**Defense note (tie-break).** When several coders are burned in the same
scan, the one reported is the lowest index (ascending scan, first found).
The defense may ask for another rule (for example: on a tie, the highest ID).
The design keeps that change local to the selection helper, and no sealed
test pins the winner (AC2):

- *Highest ID among the burned coders of the scan:* scan in descending order
  (the loop in the helper only).
- *Earliest deadline, ties to the highest ID:* in the helper, scan every
  coder, keep the burned one with the smallest `last_compile_start` (same
  deadline ⇔ same start, since `time_to_burnout` is shared) and on equality
  keep the higher index. Caution (Codex advisory): re-reading
  `last_compile_start` after `get_burned_out` may see a renewal and sort by a
  value other than the one that justified the burnout; a coherent snapshot
  needs the start read in the same critical section as the check (for
  example an extra `long *start` out-parameter on `get_burned_out`), so this
  variant is more work and its Norm fit must be checked on the code. The
  routine is unchanged in both variants.

Not implemented now (user decision 2026-11-05); recorded so the live change
stays small.

**Latency budget.** One slice (≤ 1 ms) plus one scan plus the `write` of the
line. The ≤ 10 ms guarantee assumes the output is consumed and normal
scheduling (`write` can block on a full pipe).

**One coder.** No special case: the single coder holds its only dongle and
never compiles (7.3.1), so the monitor reports its burnout at
`time_to_burnout` when the target is positive.

**Preconditions.** The simulation was built by `init_simulation` from a
configuration validated by `parse_config`, `start_ms` is set before the
monitor thread starts and not changed afterwards, and the simulation outlives
the thread (joined before `free_sim`, phase 09).

**Lock order.** The routine locks no mutex directly; each helper takes and
releases its own: coder mutex as a leaf (8.1.1, 8.1.2); `log_mutex` then
`stop_mutex` nested inside `print_burnout` and `set_stopped`; `stop_mutex` in
`is_stopped`; dongle mutexes inside `wake_dongles`. No helper is called while
another one holds a mutex.

**Norm fit.** Five functions of at most 25 lines look feasible: the
selection helper, the stop-and-wake exit, one scan step, the burnout
handling, and the public routine (to be confirmed on the code).
