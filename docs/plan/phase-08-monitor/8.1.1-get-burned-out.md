## Description

`int get_burned_out(t_coder *coder, int *burned)` in
`coders/src/monitor/get_burned_out.c`: tells the monitor (8.2.1) whether
one coder missed its deadline. Subject: a coder burns out if it does not start
compiling within `time_to_burnout` ms of the start of its last compile or of
the simulation start; the deadline is `last_compile_start + time_to_burnout`
on the simulation clock (PLAN.md edf time base, `last_compile_start` 0 before
the first compile).

**Contract.** Validate, lock the coder mutex, read `last_compile_start` and
`now = get_elapsed_ms(sim->start_ms)`, unlock, then set `*burned` to 1 iff
`now - last_compile_start >= time_to_burnout`, else 0 (mathematical notation;
the code compares without overflow, see Code review check). User decision
2026-11-05, Codex advisory: reaching the deadline already burns; `>` would
grant one extra ms with the integer clock. Reading both values inside one
critical section closes the race where the coder renews its start between the
two reads, mirroring `set_compile_start`, which reads the clock under the same
lock. 0 on success; -1 on NULL input, clock failure (unlock first), lock
failure or unlock failure; `*burned` unchanged on every -1. The result
describes that instant: a burnout observed this way is terminal for the
monitor, a later renewal does not revoke it.

A coder that already met its own compile target can still burn out (the run
only ends when every coder met it, subject). Never logs: printing the burnout
line is the monitor's job through `print_burnout`.

**Preconditions.** The simulation was built by `init_simulation` (coder mutex
initialised) from a configuration validated by `parse_config` and not changed
afterwards (in particular `time_to_burnout >= 1`); `burned` points to storage
that is not a field of the coder or the simulation; `start_ms` is set before
any thread starts and not changed afterwards; the caller does not already hold
this coder's mutex.

**Lock order.** The coder mutex is a leaf: nothing else is locked while it is
held.

**Name.** `get_` reads or computes a value without changing anything
(`docs/conventions.md`); `is_` is not used because it must return 0 or 1, and
here the answer goes in an out-parameter so -1 can report a failure (0/-1
convention). Checked: no `get_burned_out` exists in `tests/` or `coders/`.
