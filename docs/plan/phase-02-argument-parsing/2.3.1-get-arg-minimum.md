## Description

`int get_arg_minimum(int position)` in `coders/src/parsing/get_arg_minimum.c` (core: no
output, no pthread, no clock). It is the **single source of truth** for the
minimum of each numeric argument, by its position in `argv` (1..7, subject
order). Both the validator (`parse_config`, 2.3.3) and the error message
(`print_arg_error`, 2.4.1) read it, so a minimum can never differ between what
is checked and what the user is told.

| Position | Field | Minimum | Source |
|---|---|---|---|
| 1 | `number_of_coders` | 1 | deduced: coders are numbered 1..`number_of_coders` and there are as many dongles; 0 means no simulation |
| 2 | `time_to_burnout` | 1 | project decision (roadmap): 0 would burn everyone out at instant 0 |
| 3-7 | `time_to_compile`, `time_to_debug`, `time_to_refactor`, `number_of_compiles_required`, `dongle_cooldown` | 0 | subject: reject negatives; 0 is not negative |

The subject sets no explicit minimum; it only says to reject negative numbers,
non-integers and a scheduler other than `fifo`/`edf`. Position 8 (scheduler) and
any position outside 1..8 have no numeric minimum and return -1 (no valid
minimum is negative, so -1 cannot be mistaken for one). The upper bound
`INT_MAX` is not here: it is enforced by `parse_number` (2.1.2).

> Input-normalisation rules may change in the future (user decision, 2026-10-27;
> see `PLAN.md`, Input validation).
