## Description

`int parse_number(const char *str, int *out)` in `coders/src/parsing/parse_number.c`
(core: no output, no pthread, no clock; no library function).

- It calls `trim_span` (2.1.1) and parses **only the span**; it never trims on
  its own (no duplicated whitespace logic).
- Valid span: one or more ASCII digits `'0'..'9'` and nothing else. No sign
  (not even `"-0"`/`"+0"`: the rule is "digits only", not "non-negative"), no
  inner whitespace, no empty span, no non-ASCII byte (compare against the
  `'0'..'9'` range; never rely on `c - '0'` alone, `char` may be signed).
  Leading zeros are allowed and do not count toward the limit: validity depends
  on the value, not on the length (`"007"` is 7, 30 zeros then `"42"` is 42).
- The value must be `<= INT_MAX` (2147483647). The overflow check runs **before**
  each multiply/add (`value > (INT_MAX - digit) / 10` style), so no signed
  overflow happens on any input length. `INT_MAX` comes from `<limits.h>`,
  included in the `.c` file, not in `main.h`.
- Returns 0 and writes the value to `*out` on success; returns -1 and does not
  touch `*out` on any failure. `str == NULL` or `out == NULL` also return -1.
- Range minimums per field are **not** checked here (`parse_config`, 2.2.3,
  applies them through `arg_minimum`, 2.2.1).

Overflow is proven by behaviour, not by a sanitizer (the test pipeline has no
UBSan step): the 2^32 + 42 and 2^64 + 42 inputs turn into a valid-looking value
under any implementation that accumulates first and checks afterwards.

`atoi` is allowed by the subject but cannot report errors or overflow, so it is
not used. `main.h` gains the prototype; `coders/Makefile` adds the source to
`SRC` (objects still depend on `main.h`, no relink).

Note for later phases (not part of this subtask): accepting values up to
`INT_MAX` means the edf key `last_compile_start + time_to_burnout` (phase 04)
must be computed in `long`, the sliced sleep (phase 03) must never pass `usleep`
1 s or more, and a huge `number_of_coders` must make init fail cleanly (phase 05).
