## Description

First step of an expand-and-contract rename (user decision 2026-10-27,
`style/project-conventions`): "span" becomes "slice", a view into a string
that owns nothing. To keep **one** trimming implementation at every close
(DRY), the new function starts as a thin delegate:

- 2.2.4 (this): `trim_slice` calls `trim_span` and copies `start`/`len` into
  a `t_slice`.
- 2.2.5: `parse_number` switches to `trim_slice`.
- 2.2.6: the algorithm moves into `trim_slice`; `trim_span` becomes the delegate.
- 2.2.7: `trim_span` and `t_span` are removed.

`main.h`: `t_slice` goes in Types (after `t_span`) and the `trim_slice`
prototype goes in the Utils section (after `trim_span`):

```c
typedef struct s_slice
{
	const char	*start;
	int			len;
}	t_slice;

t_slice	trim_slice(const char *str);
```

`coders/src/utils/trim_slice.c` (own 42 header via `:Stdheader`) defines only
`trim_slice`. Both functions live in `utils/` since 2.2.2, so the delegation
never makes `utils/` depend on another module; 2.2.6 reverses its direction.

Code review check: `trim_slice` has no trimming logic of its own; it only calls
`trim_span` and maps the result.
