## Description

Reusable primitive so whitespace handling exists in exactly one place. Its
first user is `parse_number` (2.1.2). The scheduler does **not** use it: the
subject requires it to be exactly `fifo` or `edf` (roadmap review, 2026-10-27).

`main.h` gains:

```c
typedef struct s_span
{
	const char	*start;
	int			len;
}	t_span;

t_span	trim_span(const char *str);
```

`len` is `int` so `main.h` needs no system header; an argument never comes close
to `INT_MAX` bytes.

`trim_span` in `coders/src/parsing/trim_span.c` (core: no output, no pthread,
no clock, no allocation):

- Whitespace is the six C-locale `isspace` characters: `' '`, `'\t'`, `'\n'`,
  `'\v'`, `'\f'`, `'\r'`, tested by a `static` helper (`isspace` is not in the
  subject's allowed list).
- Skips leading whitespace, then measures up to the last non-whitespace byte.
  `start` points **into** the input (no copy) and the input is never modified
  (`argv` stays intact).
- Empty or all-whitespace input gives `len` 0 (`start` is then unspecified but
  non-NULL). `NULL` gives `{NULL, 0}`.
- It does not decide what is valid: an empty span or inner whitespace is
  rejected by the parsers that use it.

> Input-normalisation rules may change in the future (user decision, 2026-10-27;
> see `PLAN.md`, Input validation).
