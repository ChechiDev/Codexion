## Description

Third step of the span → slice rename: the delegation of 2.2.4 is reversed so
the algorithm lives in its final place and there is still only **one**
implementation.

- `coders/src/utils/trim_slice.c` gets the algorithm, same contract as 2.1.1:
  skip leading whitespace, take the length with `strlen` (authorized; never
  reimplemented), then step back over trailing whitespace. Whitespace is the six
  C-locale `isspace` characters, tested inline for now (`is_space` arrives in
  2.2.8, and 2.2.9 switches to it). `strlen` returns `size_t`; `len` stays `int`
  (2.1.1 rationale), explicit cast. No `static` helper, so no clash when the
  public `is_space` arrives.
- `coders/src/utils/trim_span.c` becomes a delegate: it calls `trim_slice` and
  copies `start`/`len` into a `t_span`. Its `static is_space` goes away.
- The delegation direction of 2.2.4 is reversed: `trim_span` (deleted in 2.2.7)
  now depends on `trim_slice`, both inside `utils/`.
- Refresh the `Updated:` header line of both files.

Code review check: the trimming algorithm exists only in `trim_slice.c` (length
via `strlen`); `trim_span` only calls `trim_slice` and maps the result; no
`static is_space` remains.
