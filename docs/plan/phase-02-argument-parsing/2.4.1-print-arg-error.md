## Description

`void print_arg_error(int position)` in its own file
`coders/src/cli/print_arg_error.c` (interfaces: it writes output). It maps the
position of an invalid argument (one set bit of the `parse_config` mask, 2.3.3)
to one line on stderr, written with `fprintf` (allowed).

- Positions 1..7: `Error: <name> must be an integer from <min> to <max>\n`.
  `<min>` is `get_arg_minimum(position)` (2.3.1, single source of the minimums) and
  `<max>` is `INT_MAX` printed with `%d` (the same bound `parse_number` enforces),
  so no limit is written twice. `<limits.h>` and `<stdio.h>` are included in the
  `.c` file, not in `main.h`.
- Position 8: `Error: scheduler must be fifo or edf\n`, using the subject's name
  `scheduler` although the field is `mode`.
- Any other position writes nothing.
- The argument names live in a local `static const` table inside the function,
  in the subject's order: no globals.

**Why `coders/src/cli/`.** `cli/` owns every user-facing message
(`docs/architecture.md`); since 2.2.1 it already holds `print_usage`. Tests link
every `coders/` object except `main.o`, so in its own file the function is
testable directly and `main.c` keeps only the entry point. It belongs to the
Interface layer (depends on core, never the other way round).

**Known duplication, kept on purpose.** The eight names also appear inside the
fixed usage text of `print_usage` (`cli/print_usage.c`; its literal output is
sealed by `tests/acceptance/test_1.2.3.c`). Rebuilding the usage from this table
would change a sealed, user-visible text for no behavioural gain, so the two
stay separate.
