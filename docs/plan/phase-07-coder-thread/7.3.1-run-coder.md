- Entry: signature `void *run_coder(void *arg)`, usable as a `pthread_create` start routine, always returns NULL; NULL `arg` or NULL `coder->sim` returns NULL touching nothing.
- Acquisition: `take_coder_dongles` (7.2.1) with a local `taken`; -1 → exit policy **without** a release (ownership not guaranteed; 7.2.1 already made its own single release attempt when it knew it held the dongles); `taken == 0` → return NULL (normal stop, nothing held); `taken == 1` → an ownership flag is set.
- Pair cycle: `set_compile_start` (7.1.1), `print_state(STATE_COMPILING)`, `sleep_ms(time_to_compile)`, `set_compile_count` (7.1.2) only after that sleep returned 0, release, `print_state(STATE_DEBUGGING)`, `sleep_ms(time_to_debug)`, `print_state(STATE_REFACTORING)`, `sleep_ms(time_to_refactor)`, then `is_stopped` (a `stop_mutex` failure reads as stopped, 3.2.1) → return NULL, else the next cycle. Each step stops the cycle at its first -1.
- Single coder (`first_dongle == second_dongle`): the static wait repeats a positive `sleep_ms` until one returns -1, and never prints anything (no `burned out`: the monitor's job); then the release; a release -1 enters the exit policy even when stopped; otherwise `is_stopped` true → return NULL, false (clock failure) → exit policy.
- Release: the ownership flag is cleared **before** each `release_dongles` attempt, so there is at most one release attempt per take and never a retry, even when it returns -1 (an attempt does not guarantee the dongles became available, 6.3.3).
- Exit policy for any -1 (setter, `print_state`, `sleep_ms` = stop or clock failure, `release_dongles`): if the ownership flag is set, one release attempt (as above); then `set_stopped` and `wake_dongles`, both always called, `wake_dongles` even when `set_stopped` returned -1; their results are not retried; return NULL. On a real stop this changes nothing (both idempotent).
- Locks: the function locks no mutex itself, so none of its own is held across a log or a sleep; after a dependency's unlock failure (e.g. `log_mutex` or a dongle mutex left held) the cleanup is best effort and may block: that synchronization failure is unrecoverable and accepted.

## Description

`void *run_coder(void *arg)` in `coders/src/coder/run_coder.c`: the body of a
coder thread (`arg` is its `t_coder *`). Subject: a coder takes two dongles,
compiles holding them, gives them back, debugs, refactors, and right after
refactoring tries to take the dongles again; PLAN.md "Coder thread".

**Cycle.** take (7.2.1, which logs `has taken a dongle`) → `set_compile_start`
→ `is compiling` → sleep `time_to_compile` → `set_compile_count` (a completed
compile only) → release → `is debugging` → sleep `time_to_debug` →
`is refactoring` → sleep `time_to_refactor` → stop check → again. The compile
start is stored before the `is compiling` line. The end-of-cycle stop check
guarantees the loop ends even when every sleep is zero-length (a zero-length
`sleep_ms` returns without checking the stop); acquisition and logging also
observe the stop.

**One coder.** One coder has one dongle (seat mapping, 5.x): it takes it, logs
it once, never compiles, and waits in sliced sleeps until the run is stopped
(the monitor of phase 08 stops it at `time_to_burnout` and prints the
`burned out` line, never this routine). It then releases the dongle and leaves.

**Stop and exit policy.** A normal stop is seen as `taken == 0`, as a -1 from
`print_state` or `sleep_ms` after a stop, or at the end-of-cycle check.
Because `print_state` and `sleep_ms` return -1 both on a stop and on a real
failure, every -1 takes one path: one release attempt if the dongles are
held, then `set_stopped` + `wake_dongles`. On a real stop this changes nothing
(both are idempotent); on a real failure it ends the whole run, so no
neighbour waits forever on a coder that is gone. After an unlock failure in a
dependency this cleanup is best effort.

**Return.** Always NULL. Telling a failure from a normal end (for a non-zero
exit status) is an open point for the lifecycle (phase 09).

**Preconditions.** Simulation built by `init_simulation`; `start_ms` set before
any coder thread starts and not changed afterwards; one thread per coder; the
thread starts holding no mutex.

**Name.** `run_` is the body of a thread routine (`docs/conventions.md`,
example `run_coder`). Checked: no `run_coder` helper exists in `tests/` or
`coders/`.

Orchestration (PLAN.md layers: `coder` module, uses `dongle`, `log`, `time`,
`state`). Close-time documentation: the `coder/` row of `docs/architecture.md`
describes the cycle and the exit policy.

**README.** No close-time update (no user-visible change until phase 09).
