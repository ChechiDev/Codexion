## Description

`int take_coder_dongles(t_coder *coder, int *taken)` in
`coders/src/coder/take_coder_dongles.c`: the coder's acquisition step with its
logs (subject 5.1: `timestamp_in_ms X has taken a dongle`, one line per dongle
taken). Phase 06 left the logging to the caller (6.3.4, 6.3.5 "Return
contract").

**Contract.** One coder (`first_dongle == second_dongle`) uses
`take_single_dongle`, any other uses `take_dongles`. Then one
`has taken a dongle` line per distinct dongle (two, or one).

**Return.** 0 with `*taken = 1`: the dongles are held and every line was
written. 0 with `*taken = 0`: a stop was observed, nothing held (either the
take saw the stop, or a log failed, the dongles were released successfully and
`is_stopped` then answered 1, which includes its `stop_mutex` error fallback,
3.2.1). -1 with `*taken` untouched: invalid input; an acquisition failure
(6.3.4 / 6.3.5 handle it, including any fatal path, as their specs define;
ownership is not guaranteed, since they may fail on an unlock after marking
dongles taken); or a log failure with
no stop observed, after one release attempt (a successful release gives the
dongles back; a failed one leaves ownership uncertain and is never retried).
The caller (7.3.1) applies its exit policy (`set_stopped` + `wake_dongles`).

**Stop precedence after a log -1.** `print_state` (3.4.3) returns -1 both
when the run is stopped (the line is dropped on purpose) and on a write or
clock failure, and a later `is_stopped` cannot tell which. The rule is stop
precedence: if a stop is observed after the release, the call ends as a normal
stop (`*taken = 0`, 0), even if the log really failed and a stop happened to
arrive meanwhile; the run is ending either way.

**Preconditions.** Simulation built by `init_simulation`, `start_ms` set
before the threads start, the caller holds no dongle, coder, log, stop or
ticket mutex (the acquisition takes a ticket, 6.1.1).

**Name.** `take_` acquires a shared resource (`docs/conventions.md`). Checked:
no `take_coder_dongles` helper exists in `tests/` or `coders/`.

Orchestration (PLAN.md layers: `coder` module, uses `dongle` and `log`).
Close-time documentation: the `coder/` row of `docs/architecture.md`.

**README.** No close-time update (no user-visible change until phase 09).
