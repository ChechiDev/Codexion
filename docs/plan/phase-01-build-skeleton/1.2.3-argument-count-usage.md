## Description

`main(int argc, char **argv)` checks that exactly 8 arguments were given
(`argc == 9`). Otherwise it calls `print_usage()` and returns `EXIT_USAGE` (1)
before doing anything else (no allocation, no threads).

`print_usage(void)` writes the usage text to stderr with `fprintf(stderr, ...)`
(allowed). `<stdio.h>` is included in `coders/main.c`, where `fprintf` is called,
**not** in `main.h`: the shared header stays free of platform headers because
core modules include it. `main.h` only gains `EXIT_USAGE` (1) and the
`print_usage(void)` prototype, which phase 02 reuses for every invalid value.

`README.md`: the Instructions part grows with how to run the program, each of
the eight arguments explained in plain words, and the real output of a
wrong-argument-count run (`docs/conventions.md` README rules). The argument keeps
the subject's name `scheduler`, even though the code stores it in `mode` (1.2.2).

What happens with exactly 8 arguments is **not** specified here (phase 02 adds
parsing, phase 09 the run); acceptance tests must not assert it.
