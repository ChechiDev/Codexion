## Description

`int sleep_start_turn(t_coder *coder)` delays even seats by `START_TURN_MS`
(1 ms), once, before their first dongle request. It returns the `sleep_ms`
result: 0 when the wait finished, 1 when the simulation stopped, -1 on error.
`START_TURN_MS` is the single place to tune the offset, at compile time: the
subject fixes the eight arguments.

**Why.** Observed on the current code (not a guaranteed order): threads usually
take their tickets in seat order, so each coder heads a queue its right
neighbour also needs while being blocked by its left one. The "head of both
heaps" rule then chains them and only one coder compiles at a time
(`5 800 200 200 200 3 0 edf` burns out in every run). When the odd seats queue
first, non-neighbouring coders compile in parallel from the start.

**A heuristic, not a guarantee.** The operating system may delay an odd thread
beyond 1 ms; the start-up then degrades to the previous behaviour, which is
still safe under the PLAN.md viability condition.

**Subject.** Arbitration is untouched: the even seat's request really arrives
later and is still served by the fifo/edf order (subject 6.1.5). The burnout
clock still starts at the simulation start (5.2.2), and the seat number is the
coder's own data, so coders do not communicate (4.7). It is a one-time start-up
offset, so "immediately after refactoring" (5.2.5) is unaffected.

**Name.** `sleep_` is in the closed verb list. Checked: no `sleep_start_turn` or
`START_TURN_MS` exists in `tests/` or `coders/`.
