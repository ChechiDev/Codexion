## Turn command-line values into a configuration

The configuration parser connects the small parsing rules into one operation.
The caller supplies the process argument vector after checking that it has the
expected number of arguments. Positions 1 through 7 are numeric fields, each
parsed by the shared number parser and checked against the minimum associated
with that position. Position 8 is the scheduler and must match the exact
`fifo` or `edf` spelling.

For example, this argument vector produces a populated configuration and a
success result:

```text
codexion 4 800 200 200 200 3 50 edf
```

The values map by position to `number_of_coders`, `time_to_burnout`,
`time_to_compile`, `time_to_debug`, `time_to_refactor`,
`number_of_compiles_required`, `dongle_cooldown`, and `mode`. Numeric values
use the established trimming and integer rules; the scheduler remains exact
and untrimmed.

Instead of stopping at the first invalid value, the parser records each
position in a bit mask. Bit 0 is reserved, and bit *n* represents argument
position *n*:

| Invalid positions | Return value |
|---|---:|
| none | `0` |
| 1 | `1 << 1` (`2`) |
| 2, 3, and 8 | `(1 << 2) \| (1 << 3) \| (1 << 8)` (`268`) |
| 1 through 8 | `0x1FE` (`510`) |

This lets the interface report every invalid argument in order. If the return
mask is nonzero, the configuration contents are unspecified and must not be
used. The parser itself performs no output, allocation, or platform work, and
leaves each input string unchanged.

<!-- section: planning -->
## How it was planned

The approved spec declares a core parser in
[[coders/src/parsing/parse_config.c]], its public declaration in
[[coders/main.h]], and its build entry in [[coders/Makefile]]. The acceptance
criteria cover a complete EDF configuration, minimum FIFO values, shared
numeric trimming, each field's lower bound, invalid values at every position,
combined error masks, argument immutability, and build and Norm requirements.
The design composes the existing `parse_number`, `get_arg_minimum`, and
`parse_mode` contracts rather than duplicating those rules.

<!-- section: execution -->
## How it was executed

The implementation maps the seven numeric destinations once, then visits
positions 1 through 7 and applies the same field parser to each. It accumulates
the position bit for each failure and checks the scheduler after the numeric
fields, so one call reports all invalid positions. Reusing the minimum lookup
keeps validation aligned with the error descriptions that the CLI will use;
delegating mode recognition preserves its exact-match behavior.

<!-- section: problems -->
## Problems & resolution

Code review requested that the static helper name follow the project's allowed
verb prefixes. The helper was renamed to `set_field_addresses`, after which
the code review approved the implementation.
