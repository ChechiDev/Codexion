<!-- section: concept -->
## A header organized by responsibility

`main.h` is the one public header shared by the deliverable's C files. Its
include guard makes repeated inclusion safe, while titled sections let a reader
find constants, shared data types, and module interfaces without changing the
API itself.

The layout follows the project's dependency direction:

```text
include guard
  Macros       EXIT_USAGE
  Types        t_mode, t_config, t_span
  Utils        trim_span
  Parsing      parse_number
  CLI          print_usage
end guard
```

For example, `parse_number` belongs under **Parsing** because it is defined by
that module; `trim_span` belongs under **Utils** after its move in 2.2.2. A
prototype in the header declares the shared contract, while its implementation
remains in the matching `.c` file. The section title is navigation, not a new
namespace or behavior.

Keeping the types before the prototypes also ensures that declarations using
those types can be understood in order. The include guard encloses every
section, so any translation unit can include the header once or more without
duplicate declarations.

<!-- section: planning -->
## How it was planned

The approved scope was a single file, `coders/main.h`: reorder existing
declarations into the `Macros`, `Types`, `Utils`, `Parsing`, and `CLI` sections
required by [[docs/conventions.md]]. Acceptance criteria require those titles
once and in order inside the guard, representative declarations in their proper
sections, preservation of the existing public declarations, and a clean build
and Norm check. This was a layout-only change with no API change.

<!-- section: execution -->
## How it was executed

The existing declarations were grouped by their owning module while retaining
their spellings and signatures. `EXIT_USAGE` is under Macros; `t_mode`,
`t_config`, and `t_span` are under Types; the span helper is under Utils;
`parse_number` is under Parsing; and `print_usage` is under CLI. No system
headers were added. The resulting arrangement makes the single-header
convention visible to future additions without introducing a dependency or
runtime behavior.
