<!-- section: concept -->
## Keep user-facing output in the CLI layer

The entry point should coordinate work, while the CLI layer owns the words shown to a user. Moving `print_usage` into `src/cli/` gives that output one clear home without changing its contract or its text. The existing argument-count check still decides when usage is needed; `main` calls the function and exits with the same status as before.

The public function can also be linked and called without the program entry point. That makes its ownership explicit and keeps the output routine independently reusable by the command-line interface.

```text
wrong argument count
        │
        ▼
      main ──calls──> print_usage ──writes──> stderr
```

The function preserves the established usage text exactly, writes nothing to standard output, and leaves the argument-count behavior unchanged.

<!-- section: planning -->
## How it was planned

Subtask 2.2.1 applies the architecture rule that `cli/` owns user-facing messages. The approved scope declares three files: add `coders/src/cli/print_usage.c`, remove the function definition from `coders/main.c` while leaving `main` as the sole function there, and register the new source in `coders/Makefile`. Acceptance criteria preserve wrong-count behavior and exact output, demonstrate that `print_usage()` links without `main.c`, and check the deliverable build, no-relink behavior, and Norm.

The prototype in `main.h` intentionally remains in place; a later subtask handles header section placement.

<!-- section: execution -->
## How it was executed

The function body was moved verbatim into its own CLI translation unit, retaining its output contract. `main` continues to perform the argument-count check and delegates the message to the CLI function. Registering the new source in the deliverable Makefile makes it part of the executable and lets callers link the routine independently of `main.c`.
