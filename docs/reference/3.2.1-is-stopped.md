## Reading a shared stop flag safely

The simulation's `stopped` field is shared state. Once multiple threads can
read and write it, every access needs the same synchronization rule. Here,
`stop_mutex` protects that flag: the reader locks it, copies the value, and
unlocks it before returning.

```text
caller                 is_stopped                  simulation state
  |                         |                              |
  |------------------------>| lock(stop_mutex)              |
  |                         |----------------------------->|
  |                         | read stopped                  |
  |                         | unlock(stop_mutex)            |
  |<------------------------| 0 = running, 1 = stopped      |
```

For example, a caller can use the result to decide whether it should continue
working:

| Protected flag | Return value | Meaning |
|---:|---:|---|
| `0` | `0` | The simulation is running. |
| `1` | `1` | The simulation has stopped. |

If acquiring or releasing the mutex fails, the function returns `1`. This is a
deliberately conservative predicate contract: a thread that cannot safely
inspect shared state must stop its own work. It does not change the shared flag
or notify other threads. The mutex is guaranteed to be released only when both
mutex operations succeed.

The function takes only `stop_mutex`; it does not take `log_mutex`. This keeps
it independent of output serialization and preserves the project's lock order.
Callers must not invoke it while already holding `stop_mutex`.

<!-- section: planning -->
## How it was planned

The subtask places the shared stop predicate in `src/state/`, exposes the
minimal simulation type and function in `main.h`, and adds the source to the
deliverable Makefile. Its acceptance criteria cover both flag values, release
of the mutex, the conservative lock-failure result, independence from
`log_mutex`, and the build and Norm checks. The plan also establishes that the
mutexes are initialized before worker use and that later simulation code keeps
the flag protected by `stop_mutex`.

<!-- section: execution -->
## How it was executed

The implementation follows the single-lock read contract: it checks the
`pthread_mutex_lock` result before reading, copies the flag while protected,
then checks the unlock result before returning the copied value. Either mutex
operation failing maps to the safe return value `1`. The state adapter is
separate from the logger so consumers across the simulation can share the same
stop-state access without coupling the state read to output.

<!-- section: problems -->
## Problems & resolution

The earlier acceptance oracle for header organization prohibited system
includes in `main.h`. The plan gate migrated that oracle to permit the one
`pthread.h` include required for the shared mutex type and resealed it. No
implementation problems remained at close.
