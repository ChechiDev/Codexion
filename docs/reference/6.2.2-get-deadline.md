## Build an absolute deadline for a timed wait

`pthread_cond_timedwait` expects an absolute `struct timespec`, not a duration.
`get_deadline(ms, &deadline)` reads the wall clock and adds `ms` milliseconds
to that instant. The result is suitable for bounding a condition-variable wait.

For example, if the clock reads 12:34:56.789 and the requested delay is 250 ms,
the deadline is 12:34:57.039. A `timespec` stores this as whole seconds and
nanoseconds within the second:

| Field | Example meaning |
|---|---|
| `tv_sec` | Whole seconds in the absolute clock time |
| `tv_nsec` | Nanoseconds within that second, always from 0 through 999,999,999 |

The fractional part may cross a second boundary. The calculation carries each
full billion nanoseconds into `tv_sec`, leaving `tv_nsec` normalized. The
subtask reads the clock once, so both fields describe one consistent deadline.
It uses `gettimeofday`, which shares the default `CLOCK_REALTIME` time base used
by `pthread_cond_timedwait`.

This absolute wall-clock value has a different purpose from the elapsed
simulation time used by arbitration. `released_at`, cooldown comparisons, and
EDF request keys are measured from `start_ms`; the timed-wait deadline is tied
to the system clock because that is the clock the condition wait compares.

The output is written only after validation and the seconds-bound check succeed.
Negative delays, a null output pointer, a clock error, or an unrepresentable
deadline return `-1` and leave the caller's output untouched. A large delay such
as `LONG_MAX` is valid on the supported 64-bit target because the resulting
seconds still fit; overflow rejection applies only when the actual `time_t`
limit would be exceeded.

<!-- section: planning -->
## How it was planned

The approved spec places one clock-reading function in the `time/` adapter and
declares its source file, the public declaration in `coders/main.h`, and the
build entry in `coders/Makefile`. Its acceptance criteria cover zero and
positive delays, normalized output, use with `pthread_cond_timedwait`, invalid
inputs with output preservation, and a large representable deadline. The helper
provides the bounded wait used by the later dongle-wait operation.

<!-- section: execution -->
## How it was executed

The implementation validates the output pointer and delay before reading the
clock, calls `gettimeofday` once, computes the nanosecond carry, checks the
seconds addition, and writes the result only on success. Keeping the absolute
deadline calculation in this adapter leaves elapsed simulation-time policy
separate. The architecture map now identifies both clock forms owned by
`time/`: elapsed time and absolute timed-wait deadlines.

<!-- section: problems -->
## Problems & resolution

The first phase review found that the plan treated `LONG_MAX` milliseconds as
necessarily overflowing. On the 64-bit target, `LONG_MAX / 1000` plus the
current epoch fits in `tv_sec`, so that expectation contradicted the intended
representable-deadline contract. The plan was corrected to require success for
that case and retain failure only for a genuine `time_t` overflow; the revised
acceptance criterion and dependency sequencing were approved by the phase gate.
