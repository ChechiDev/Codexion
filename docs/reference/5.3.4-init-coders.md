## Constructing the coder ring as one owned array

`init_coders` creates the per-coder state for a circular simulation. The array
index is the zero-based seat; each coder's public id is one-based, while the
dongle indices come from the shared ring mapping. For four coders:

| Array index (seat) | Coder id | First dongle | Second dongle |
|---:|---:|---:|---:|
| 0 | 1 | 0 | 1 |
| 1 | 2 | 1 | 2 |
| 2 | 3 | 2 | 3 |
| 3 | 4 | 0 | 3 |

The initializer allocates the array and initializes its elements in seat
order. Each element receives its own mutex and starts with
`last_compile_start = 0` and `compile_count = 0`. The simulation pointer is
borrowed: it is stored for later use but never dereferenced while constructing
the array. The thread field belongs to later thread lifecycle work and is not
needed here.

Construction has a clear ownership boundary:

```text
validate arguments and size
            │
       allocate array
            │
 initialize seats 0..n-1 ── success ──> publish *out; caller owns array
            │
          failure ───────────> free initialized prefix; return -1
```

For `n = 1`, the coder's two dongle indices are both zero because the ring has
one dongle. For any positive `n`, success gives the caller an array of exactly
`n` fully initialized coders, released later with `free_coders(coders, n)`.
If initializing seat `k` fails, only seats `[0, k)` have live mutexes; passing
that initialized-prefix count to `free_coders` avoids destroying uninitialized
mutexes. The output pointer is written only after the entire array succeeds,
so a failure leaves the caller's previous value intact.

<!-- section: planning -->
## How it was planned

The approved subtask adds `init_coders` in the adapter lifecycle layer. Its
three declared production files are the new initializer source, the prototype
in `coders/main.h`, and the source entry in `coders/Makefile`. Acceptance
criteria cover four-seat mapping and initial state, one and large arrays,
independent coder mutexes, cleanup through `free_coders`, and invalid inputs
without changing the output pointer. Allocation and element-initialization
failures are handled by the sealed code-review check because they cannot be
forced deterministically through the public API.

<!-- section: execution -->
## How it was executed

The implementation checks pointers, positive count, and the `size_t` allocation
bound before allocating. It delegates each record to `init_coder`, keeping
field setup, ring mapping, and mutex creation in the existing per-coder
lifecycle operation. If an element fails, `free_coders` releases exactly the
successfully initialized prefix and the allocated array. This makes normal
construction and rollback share one teardown path. `*out` is assigned only
after every element succeeds; `sim` remains a borrowed back pointer throughout.
