## A trimmed slice is a view into the original string

A slice describes a piece of text using a starting pointer and a length. It
does not copy the characters or own storage, so the caller can inspect the
trimmed text without allocating a second string or modifying the input.

For example, trimming `"     0007     "` produces a view like this:

```text
input:       "     0007     \0"
                         ^
slice.start:             '0'
slice.len:               4
```

The pointer remains inside the original string and `len` tells the caller
exactly how many characters belong to the view. Inner whitespace is retained:
`"  fi fo  "` becomes a five-character slice containing `fi fo`. A string
with only whitespace has length zero. A null input is represented by
`{NULL, 0}`.

The view is borrowed: it is valid only while the original string remains
available, and callers must not try to free `start`. In this step,
`trim_slice` delegates to the existing `trim_span` implementation and maps its
pointer and length to the new `t_slice` type. That keeps one trimming algorithm
while consumers migrate; later steps move the algorithm and remove the old
span API.

<!-- section: planning -->
## How it was planned

The approved spec declares `coders/src/utils/trim_slice.c`, `coders/main.h`,
and `coders/Makefile`. Acceptance criteria cover the public `t_slice` fields,
leading and trailing whitespace removal, preservation of inner whitespace and
the input bytes, empty and null input, prototype placement in the Utils
section, and build, no-relink, and Norm behavior. This is the first step of
the staged span-to-slice rename; the explicit delegate avoids duplicating the
trimming logic during the transition.

<!-- section: execution -->
## How it was executed

The shared header adds `t_slice` with `const char *start` and `int len`, plus
the `trim_slice` declaration under Utils. The new utility calls `trim_span`
and transfers the resulting pointer and length into the slice. Since both
functions are core utilities, the delegation stays within the core layer; it
also preserves the non-owning, non-mutating contract without allocating or
copying text. The deliverable Makefile includes the new source.

<!-- section: problems -->
## Problems & resolution

An initial unit test compared uninitialized bytes in its local buffer. The
test was corrected to compare only initialized input bytes; no production
change was needed.
