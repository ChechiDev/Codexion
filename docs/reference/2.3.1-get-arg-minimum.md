## Look up a numeric argument's minimum

Command-line arguments have positions with meanings defined by the subject. A
minimum is part of validating numeric positions: the number of coders and time
to burnout must be at least 1, while the five remaining numeric values may be
0. The scheduler at position 8 is text, so it has no numeric minimum.

| Position | Argument | Minimum |
|---:|---|---:|
| 1 | `number_of_coders` | 1 |
| 2 | `time_to_burnout` | 1 |
| 3 | `time_to_compile` | 0 |
| 4 | `time_to_debug` | 0 |
| 5 | `time_to_refactor` | 0 |
| 6 | `number_of_compiles_required` | 0 |
| 7 | `dongle_cooldown` | 0 |
| 8 | scheduler | not numeric (`-1`) |

For instance, `get_arg_minimum(1)` returns `1`, `get_arg_minimum(5)` returns
`0`, and `get_arg_minimum(8)` returns `-1`. Positions outside the argument
range also return `-1`. The sentinel distinguishes “no numeric minimum here”
from valid minima, which are nonnegative. This function supplies a single
lookup so argument validation and the corresponding CLI error message can use
the same rule. The upper bound remains the number parser's responsibility.

<!-- section: planning -->
## How it was planned

The approved spec declares a pure core lookup in
[[coders/src/parsing/get_arg_minimum.c]], with its public declaration in
[[coders/main.h]] and build entry in [[coders/Makefile]]. Acceptance criteria
cover the two positive minima, five zero minima, the scheduler and invalid
positions, plus the build and Norm requirements.

<!-- section: execution -->
## How it was executed

The implementation maps positions 1 and 2 to 1, positions 3 through 7 to 0,
and all other positions to -1. Keeping this as a side-effect-free parsing
helper lets future validation and error reporting share the same minimum
without introducing I/O, allocation, or mutable state into the core.
