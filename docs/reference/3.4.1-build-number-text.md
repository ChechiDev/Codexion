## Writing decimal digits into a caller buffer

`build_number_text` converts a non-negative `long` into its decimal digits in a
buffer supplied by its caller. It returns the number of bytes written, so a
caller can continue assembling a larger message immediately after those bytes.
The helper writes neither a sign nor a string terminator.

```text
number:  1204
buffer:  [ '1' ][ '2' ][ '0' ][ '4' ][ untouched bytes ... ]
return:  4
```

For example, a log-line builder can append the timestamp, a space, the coder
number, and the state text into one local buffer, then pass the final byte
count to `write`. This avoids a temporary string allocation and makes the
formatted bytes directly usable by an unbuffered output call.

| Input | Bytes written | Return |
|---:|---|---:|
| `0` | `0` | 1 |
| `42` | `42` | 2 |
| `1000000` | `1000000` | 7 |
| `LONG_MAX` on the target LP64 platform | `9223372036854775807` | 19 |
| negative value or null buffer | none | -1 |

The caller must provide `NUMBER_TEXT_MAX` writable bytes (20 on the target
LP64 platform, enough for all 19 decimal digits of `LONG_MAX` plus one spare
byte). This capacity is a contract: a pointer alone does not reveal the
destination's size. Because no NUL is appended, a large conversion followed
by a small conversion in the same buffer leaves old trailing bytes in place;
callers must use the returned length and must not treat the buffer as a C
string.

<!-- section: planning -->
## How it was planned

The approved spec places this generic, pure formatting helper in
`coders/src/utils/build_number_text.c`, adds its capacity macro and prototype
to `coders/main.h`, and registers the source in `coders/Makefile`. Acceptance
criteria cover canonical decimal output, the full non-negative `long` range,
exact write bounds, invalid inputs, and build integration. The helper exists
to support the serialized logger's one-buffer, one-write contract.

<!-- section: execution -->
## How it was executed

The implementation counts the decimal digits, then fills that many positions
from right to left using quotient and remainder by ten. This preserves the
usual left-to-right representation without needing a temporary array or
reversing an intermediate string. The zero input is handled as a one-digit
value, and negative input or a null destination is rejected before any write.

The helper stays in the core layer: it has no output, allocation, clock,
threading, or global-state dependency. Its return value is deliberately the
digit count rather than a generic success code because the next buffer append
needs that exact offset; `-1` remains an unambiguous error. This is the
documented exception to the project's usual 0/-1 plus out-parameter style.
