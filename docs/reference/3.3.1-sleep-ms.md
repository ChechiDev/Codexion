## Sleeping while watching for a stop

`sleep_ms` waits for a requested duration while periodically checking whether
the simulation has stopped. A single long sleep would leave a worker unable to
notice shutdown until the whole duration elapsed. Instead, the adapter sleeps
in short slices and consults the shared stop-state API between them.

```text
start clock
    |
    v
check stopped? -- yes --> return -1
    |
    no
    v
measure elapsed -- duration reached? -- yes --> return 0
    |
    no
    v
sleep for at most 500 microseconds
    |
    +--------------------------> check stopped again
```

For example, `sleep_ms(sim, 100)` returns `0` after at least 100 milliseconds
of project-clock time, unless a stop is observed first. If another thread calls
`set_stopped` during `sleep_ms(sim, 10000)`, the next stop check makes the sleep
return `-1` rather than waiting for the full ten seconds. The 500 microsecond
slice is a requested interval, not a hard scheduling guarantee; system load and
mutex contention affect the actual response time.

| Input or event | Result | Meaning |
|---|---:|---|
| `ms <= 0` | `0` | No wait is needed; this path does not consult the clock or mutex. |
| Elapsed duration reached | `0` | The requested interval completed. |
| Stop observed | `-1` | Abandon the caller's current action. |
| Clock failure | `-1` | The time adapter could not provide a valid reading. |

The adapter derives elapsed time from the shared wall clock rather than adding
up requested sleep slices. This accounts for interrupted or shortened
`usleep` calls: after every slice it checks the clock again. A failed `usleep`
therefore causes another loop iteration, not an immediate error. Since the
clock is wall time, a backward adjustment can extend a wait; the duration
checks assume no such adjustment during the interval.

<!-- section: planning -->
## How it was planned

The approved spec assigns this time adapter to `coders/src/time/sleep_ms.c`,
with `SLEEP_SLICE_US` and the public prototype in `coders/main.h`, plus the
source entry in `coders/Makefile`. Its acceptance criteria cover immediate
returns for nonpositive durations, a completed timed wait, an already-stopped
simulation, prompt response to a concurrent stop, and build/symbol/Norm
integration. Timing slack affects upper bounds only. The design reuses the
clock and stop-state APIs introduced by the preceding subtasks.

<!-- section: execution -->
## How it was executed

The implementation returns immediately for `ms <= 0`, then records a start
timestamp. Each loop checks the stop flag before measuring elapsed time, so a
stop takes precedence if it is observed at the same iteration that the
duration has elapsed. It uses `get_elapsed_ms` to avoid subtracting raw clock
values and checks its `-1` failure result before computing the remaining time.
The slice helper caps the remaining milliseconds before converting to
microseconds, so a large positive duration cannot overflow during conversion.

No mutex is held while `usleep` runs. This allows `set_stopped` to acquire its
locks while a worker is sleeping. The loop rechecks elapsed time after every
requested slice instead of assuming the operating system slept for the full
request.

<!-- section: problems -->
## Problems & resolution

The first code review found that subtracting a negative elapsed value after a
backward wall-clock jump could overflow for a large requested duration. The
implementation now uses `get_elapsed_ms`, which clamps a future start to zero
and reports clock failure as `-1`; remaining-time subtraction occurs only
after confirming `0 <= elapsed < ms`.
