## Releasing a complete simulation

A simulation owns resources at several levels: coder records own mutexes, dongle records own mutexes, condition variables and request heaps, and the simulation itself owns the arrays and three coordinating mutexes. The outer cleanup operation releases these layers in the reverse order that construction created them.

For a simulation with three coders, the dependency sequence is:

```text
init_sim
  ├─ stop, log, ticket mutexes
  ├─ dongle array (each dongle: mutex, condition, heap)
  └─ coder array (each coder: mutex)

free_sim
  ├─ coder array and coder mutexes
  ├─ dongle array and each dongle's resources
  └─ ticket, log, stop mutexes
```

The arrays may be NULL. That makes the same cleanup function useful while initialisation is incomplete: a later initializer can initialise the coordinating mutexes, set both array pointers to NULL, then use `free_sim` to roll back whichever arrays were successfully created. Once called with valid live resources, each owned array pointer is set to NULL after release. The configuration, clock origin, stop value and request ticket counter are ordinary state, so teardown preserves them.

The function reports `0` when all teardown steps succeed and `-1` for a NULL simulation or any failed step. It continues through later resources after an error, allowing best-effort cleanup. For example, with a three-coder simulation, successful teardown leaves `sim.coders == NULL` and `sim.dongles == NULL`, while `sim.config.number_of_coders` remains 3.

The caller must ensure all three simulation mutexes are initialised and unlocked, any non-NULL arrays are fully initialised for the configured coder count, and all worker threads have been joined. The function does not join threads or acquire locks. Calling it twice is invalid because the mutexes have already been destroyed.

<!-- section: planning -->
## How it was planned

Subtask 5.4.1 declares `free_sim`, the expanded `t_sim` layout and build registration in the three files listed by the spec. Its acceptance criteria cover full and partial resource sets, preservation of non-resource state, reuse after rebuilding, the one-coder edge case and NULL input. It precedes 5.4.2 so simulation initialisation can use it for rollback.

<!-- section: execution -->
## How it was executed

The cleanup adapter delegates array teardown to `free_coders` and `free_dongles`, avoiding duplicated element-level destruction. It visits coders before dongles, then destroys the ticket, log and stop mutexes. Each failure changes the final result to `-1` without preventing later cleanup steps. The public function rejects NULL before dereferencing the simulation and leaves its non-resource fields untouched.
