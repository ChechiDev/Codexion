## Mapping a seat to its shared dongles

There are `n` seats and `n` dongles around one circle. A seat uses the dongle at its own index and the next dongle clockwise. The final seat wraps around to dongle zero:

```text
seat:     0       1       2       3
         [0] —   [1] —   [2] —   [3]
          |                       |
          └───────────────────────┘

pair:    (0,1)   (1,2)   (2,3)   (0,3)
```

`get_dongle_pair` returns the two indices in ascending order. That order is part of the synchronization contract: later code locks dongle mutexes in the same global order, preventing two coders from taking the same pair in opposite orders.

For `n == 1`, the circle contains one physical dongle, so both indices are zero. The caller must recognize this equal-index case and acquire that resource once rather than locking or enqueueing it twice.

| Input | Result |
|---|---|
| `seat = 0`, `n = 4` | success, `(0, 1)` |
| `seat = 3`, `n = 4` | success, `(0, 3)` |
| `seat = 0`, `n = 1` | success, `(0, 0)` |
| out-of-range seat, invalid `n`, or null output | `-1`; outputs remain untouched |

Validation happens before calculating or writing the result. For the final seat, wraparound is selected directly; otherwise the next index is `seat + 1`. This avoids evaluating `seat + 1` when `seat` may be `INT_MAX - 1`.

<!-- section: planning -->
## How it was planned

The approved scope is one pure core function, declared in the shared header and added to the deliverable build. The three declared production files are [[coders/src/init/get_dongle_pair.c]], [[coders/main.h]], and [[coders/Makefile]]. Acceptance criteria cover a four-seat ring, the single-coder case, two coders sharing both dongles, `INT_MAX` boundaries, and invalid inputs that must preserve caller outputs. No README change was planned because this internal mapping has no user-visible effect.

<!-- section: execution -->
## How it was executed

The helper validates pointers and index bounds first, determines the right-hand neighbour with a last-seat branch, sorts the pair into lower-index-first order, and writes both outputs only after success is certain. It needs no allocation, shared state, locks, clock access, or output, so it remains independently testable core logic. The `init` header section and Makefile source list make it available to the later coder initializer.
