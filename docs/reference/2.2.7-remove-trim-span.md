<!-- section: concept -->
## Keep one trimming view

`trim_slice` returns a non-owning view into the original string. The view has
two parts: `start` points at the first retained character, and `len` counts the
retained characters. It neither edits nor copies the input. For example:

```text
input:  "  fi fo  "
slice:      ^-----^
start:      'f'
len:        5
```

The earlier `trim_span` API returned the same information in the older
`t_span` type. Since `trim_span` had become only a delegate to `trim_slice`,
keeping both names and types created a second public spelling without a second
capability. Removing the delegate leaves one clear contract for trimming.

Empty and null inputs remain safe: `trim_slice("")` and
`trim_slice("   ")` have length zero, while `trim_slice(NULL)` returns
`{NULL, 0}`. `parse_number` continues to use the slice to parse trimmed
numeric text; for example, `parse_number("  42  ", &n)` succeeds and stores
`42`.

```text
argv text ──trim_slice──> borrowed t_slice ──parse_number──> integer
```

The view is borrowed, so its lifetime is bounded by the original string. No
allocation or ownership transfer is involved.

<!-- section: planning -->
## How it was planned

The approved scope retired the obsolete delegate as one API cleanup: remove
`trim_span.c`, remove `s_span`/`t_span` and the prototype from `main.h`, and
remove the source from the deliverable Makefile. Acceptance criteria checked
that the old names no longer compile, the `trim_slice` and `parse_number`
contracts remain intact, and the deliverable still builds cleanly without
relinking and passes Norm.

<!-- section: execution -->
## How it was executed

The implementation removed the legacy declarations and build entry after the
algorithm had already moved into `trim_slice`. The former span unit cases were
retained against the slice API, preserving coverage of edge inputs and
unchanged source text. Older acceptance oracles were migrated during the plan
gate so they follow the surviving public API. The implementation report and
approved review confirm the supplied check passed.

<!-- section: problems -->
## Problems & resolution

Older acceptance oracles still named the retired API and source path. The plan
gate migrated those checks to `trim_slice` and its source path, preserving
their criteria, then re-sealed the oracles before implementation.
