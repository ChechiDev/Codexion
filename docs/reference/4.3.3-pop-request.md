## Removing the minimum request from a heap

A binary min-heap keeps its earliest request at index `0`. Removing that
request leaves a hole at the root. The usual repair is to move the final
occupied item into the hole, shrink the occupied range, then sift the moved
item down until neither child precedes it according to
[[docs/reference/4.1.1-is-request-before.md]].

For example, suppose the heap contains these requests, where each pair is
`(key, ticket)`:

```text
Before:       [ (1,4), (3,0), (1,9), (5,1), (3,2) ]
Output copy:    (1,4)
Move last:    [ (3,2), (3,0), (1,9), (5,1) ]
Sift down:   [ (1,9), (3,0), (3,2), (5,1) ]
```

The popped value is copied to caller-owned output before the heap changes. The
last item moves to the root, then the smaller child is selected with the same
request comparator used by insertion. Here `(1,9)` moves above `(3,0)`, and
the heap property is restored. Each descent moves one level in a tree whose
height is logarithmic, so removal takes `O(log n)` comparisons.

An empty heap or NULL argument returns `-1` without changing the output or
heap. On success the size falls by one and the remaining occupied slots still
form a min-heap. The caller supplies synchronization when shared access is
possible; the operation itself is pure heap logic and takes no lock.

<!-- section: execution -->
## How it was executed

The function checks arguments and emptiness before writing, copies the root to
`*out`, then decrements the size. If entries remain, it moves the former last
entry to index zero and calls a private `sift_down`. That helper checks whether
the current node can have a child before calculating child indices, chooses
the smaller existing child, and swaps only when that child precedes the
current item. No allocation or synchronization is added; the caller retains
ownership of heap storage and locking. The existing `heap/` row in
[[docs/architecture.md]] already describes push, peek, and pop, so no
cross-cutting architecture change was needed.

Together with [[docs/reference/4.3.1-push-request.md]] and
[[docs/reference/4.3.2-get-head-request.md]], this completes the public heap
operation set. Later arbitration can inspect both dongle heap heads and pop
requests while holding the relevant locks, without needing a remove-by-coder
operation.
