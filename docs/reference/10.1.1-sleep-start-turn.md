## Staggering the first request

`sleep_start_turn` gives even-numbered seats a one-time delay before their first dongle request. Odd seats return immediately. The helper is intentionally small: it does not change who wins a request under FIFO or EDF; it changes when even seats enter that existing arbitration.

This is a start-up heuristic. If odd-seat threads reach the queue first, non-neighbouring coders can begin compiling in parallel instead of forming a chain of adjacent requests. The operating system can still delay a thread long enough to erase the stagger, so the offset improves a common schedule but does not guarantee an order or replace the plan's viability condition.

The public result follows `sleep_ms`:

| Situation | Result |
|---|---:|
| Invalid coder or missing simulation | `-1` |
| Odd seat | `0`, without reading the clock or sleeping |
| Even seat, delay completed | `0` |
| Simulation stopped during or before the delay | `1` |
| Clock or sleep error | `-1` |

`START_TURN_MS` is the single compile-time tuning point (currently 1 ms). For example, with five seats, seats 1, 3, and 5 can request immediately; seats 2 and 4 wait for the offset, then use the same FIFO/EDF queues as before. The burnout clock still starts at simulation start, and no ticket, compile count, or log entry is produced by this helper.

<!-- section: planning -->
## How it was planned

The approved scope adds one coder-orchestration function, its declaration and `START_TURN_MS` macro in the shared header, and its source entry in the deliverable Makefile. Seven acceptance criteria cover odd/even behavior, elapsed lower bound, stopped and invalid inputs, unchanged output/state, stop during the wait, and clock failure. Integration into `run_coder` is explicitly left to [[docs/plan/phase-10-hardening-and-readme/10.1.2-run-coder-start-turn.md|10.1.2]].

<!-- section: execution -->
## How it was executed

The helper validates its pointers, returns immediately for odd seat numbers, and delegates the even-seat wait to `sleep_ms`, returning that result unchanged. Reusing the existing sleep contract keeps stop and clock-error handling consistent with the rest of the simulation. The helper does not acquire locks or access request heaps, tickets, compile state, or logging; the delay therefore affects request arrival time without adding a second arbitration path.
