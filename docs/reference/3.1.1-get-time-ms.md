## Reading wall-clock time in milliseconds

A simulation needs one shared time scale for elapsed durations, sleeps and log timestamps. `get_time_ms` adapts the system wall clock to that scale: it reads seconds and microseconds with `gettimeofday`, then truncates the fractional second to whole milliseconds.

The conversion is:

```text
milliseconds = seconds × 1000 + microseconds ÷ 1000
```

For example, a reading of `tv_sec = 1,234` and `tv_usec = 567,890` becomes `1,234,567` milliseconds since the Unix epoch. Microseconds below the next millisecond are discarded; this is a millisecond clock, not a promise of millisecond scheduling precision.

The function is an adapter at the edge of the architecture. Core calculations consume its numeric result and do not call the operating system clock themselves. This keeps the source of time consistent for later elapsed-time calculations, stop-aware sleeps and logging.

Because the clock is wall time, it can be adjusted by the system. The monotonic-read checks in this subtask assume no backward adjustment during their short observation window. Durations in later simulation code therefore rely on the stated environment assumption rather than a monotonic-clock guarantee.

The function returns the timestamp directly. A failed `gettimeofday` call yields `-1`; callers must check that sentinel before arithmetic or output. With a valid local `timeval` pointer, the documented failure is not expected in normal operation, and the direct return keeps the common time path small.

<!-- section: planning -->
## How it was planned

The `3.1.1` spec scoped the adapter to `get_time_ms` in `coders/src/time/get_time_ms.c`, its declaration in the new Time section of `coders/main.h`, and the source entry in `coders/Makefile`. Acceptance criteria cover the value against surrounding `gettimeofday` readings, repeated non-decreasing results, a roughly 50 ms delay, and the build and Norm requirements. The plan records a user-approved exception to the usual status-plus-output convention: this function returns a timestamp or `-1` directly.

<!-- section: execution -->
## How it was executed

The adapter keeps the system header and syscall in the time module, while exposing only the function prototype through the single project header. It converts seconds and microseconds using integer arithmetic. This gives later adapters one clock-reading boundary and avoids spreading platform calls into core logic. The accepted error contract lets each caller propagate `-1` before it performs timestamp arithmetic or writes a log line.
