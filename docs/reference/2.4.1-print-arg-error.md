## Turn an invalid position into a useful error

The parser reports invalid inputs in a flag array whose indices match the
command-line arguments. The CLI turns each such position into a short explanation on
standard error. Numeric positions 1 through 7 name the field and state its
accepted integer range; position 8 describes the scheduler choices. For
example:

```text
Error: time_to_burnout must be an integer from 1 to 2147483647
Error: scheduler must be fifo or edf
```

The lower bound for each numeric message comes from
[[coders/src/parsing/get_arg_minimum.c]], the same lookup used when validating
the value. `INT_MAX` supplies the shared upper bound enforced by the number
parser. This keeps the diagnostic consistent with validation without
maintaining a second list of numeric limits.

Positions outside 1 through 8 have no corresponding argument and produce no
output. The function writes each message to `stderr`; it does not mutate
configuration, produce a parser result, allocate memory, or print the usage text.
The caller can therefore walk the parser's flags from left to right, print one
specific message for every invalid argument, then print usage once.

<!-- section: planning -->
## How it was planned

The approved spec declares a new CLI implementation in
[[coders/src/cli/print_arg_error.c]], its public prototype in
[[coders/main.h]], and a build entry in [[coders/Makefile]]. Acceptance criteria
cover exact messages and stderr routing for all eight positions, silence for
invalid positions, reuse of the numeric minimum lookup, and build and Norm
requirements. The design keeps user-facing output in the interface layer and
uses the existing parser rule as the source of numeric minimums.

<!-- section: execution -->
## How it was executed

The function uses a local constant table to map argument positions to their
subject field names. It checks the position before indexing that table, then
formats numeric diagnostics with the shared minimum and `INT_MAX`; the
scheduler has its own fixed message. The usage text remains owned by
`print_usage`, so this function emits only the position-specific line and can
be called once for each set flag in the parser's result.
