## Keeping one trimming algorithm at its final home

`trim_slice` returns a non-owning view of the part of a string that remains after leading and trailing whitespace are removed. The view contains a pointer to the first retained character and its length; the source string is never changed or copied. For example:

| Input | View |
|---|---|
| `"  hello\t"` | `"hello"`, length 5 |
| `"a b"` | `"a b"`, length 3 |
| `"   "` | empty view, length 0 |

The trim operation recognizes the six C-locale whitespace characters at the edges. It leaves whitespace in the middle intact and leaves other boundary bytes such as `0x01` and `0x7f` untouched. A `NULL` input produces `{NULL, 0}`.

The earlier `trim_span` API represents the same kind of range with a `t_span`. Once `t_slice` is established as the preferred view, there should be one place that performs the scan: `trim_slice`. `trim_span` can remain temporarily as a compatibility adapter that calls `trim_slice` and maps its pointer and length into `t_span`. That keeps behavior shared while callers migrate; the adapter is removed in a later subtask.

```text
input string ──> trim_slice ──> { start, len }
                      ▲
                      └── trim_span maps the same result to t_span
```

The length is obtained with the authorized `strlen` function. The public slice keeps its established `int` length, with an explicit conversion from `strlen`'s `size_t` result.

<!-- section: planning -->
## How it was planned

This was scoped as a structural refactor with no behavior change. The two declared files were [[coders/src/utils/trim_slice.c]], which takes ownership of the trimming algorithm, and [[coders/src/utils/trim_span.c]], which becomes a thin adapter. Acceptance criteria preserve the existing slice and parser behavior, check non-whitespace boundaries, and require a clean build and Norm result. The structural review check required a single algorithm in `trim_slice.c`, delegation and field mapping in `trim_span.c`, and removal of its private `is_space` helper.

<!-- section: execution -->
## How it was executed

The scanning logic now lives in `trim_slice`, using the inline whitespace predicate specified for this step and `strlen` for the initial length. `trim_span` calls `trim_slice` and copies the returned pointer and length into its existing result type. This preserves the older API without retaining a second trimming implementation, while keeping both functions in the pure `utils` layer.
