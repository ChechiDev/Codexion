<!-- section: concept -->
## Assemble one serialized log line

`build_log_line` assembles the project's log format in a caller-owned byte
buffer: a decimal timestamp, a space, a coder number, another space, the event
text, and a newline. For example:

```text
timestamp: 1204
coder:     3
event:     is compiling
bytes:     1204 3 is compiling\n
return:    20
```

The returned number is the number of bytes to send. The buffer is not a C
string: no NUL terminator is added, and bytes after the returned length remain
untouched. A caller can therefore pass the buffer and length directly to a
single `write` call.

| Input | Result |
|---|---|
| `ts = 0`, `coder = 1`, `text = "is compiling"` | `0 1 is compiling\n`, length 17 |
| `ts = 1204`, `coder = 3`, `text = "burned out"` | `1204 3 burned out\n`, length 18 |
| `ts < 0`, `coder < 1`, or invalid event text | `-1`, with no buffer changes |

The fixed capacity is 64 bytes: at most 19 timestamp digits, a separator,
10 coder digits, a separator, 32 event-text bytes, and the final newline. The
valid text is nonempty, at most 32 bytes, and cannot contain CR or LF, so each
successful result is exactly one physical log line.

<!-- section: planning -->
## How it was planned

The approved spec places this formatter in `coders/src/log/build_log_line.c`,
adds `LOG_TEXT_MAX`, `LOG_LINE_MAX`, and the public prototype to
`coders/main.h`, and registers the source in `coders/Makefile`. Acceptance
criteria cover exact bytes and write bounds, every subject event string,
maximum capacity, invalid-input no-write behavior, and build integration. The
helper is the shared format boundary for the later state and burnout printers.

<!-- section: execution -->
## How it was executed

The formatter validates the destination, timestamp, coder number, and complete
event text before writing anything. It delegates both decimal conversions to
`build_number_text`, then appends separators, the validated text, and one
newline. This keeps number formatting in the existing utility and leaves the
log module as pure core logic: it performs no output, allocation, clock read,
or locking.

Returning the byte length lets the adapter layer send exactly the initialized
portion of the buffer. Validation before the first store also gives callers an
all-or-nothing failure contract without requiring a temporary allocation.
