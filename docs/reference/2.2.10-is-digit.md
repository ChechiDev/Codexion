## Recognize decimal digits

A decimal digit is one of the ten character values from `'0'` through `'9'`.
`is_digit` answers whether a single `char` belongs to that range:

| Input | Result | Reason |
|---|---:|---|
| `'0'` | 1 | Lower boundary |
| `'5'` | 1 | Inside the range |
| `'9'` | 1 | Upper boundary |
| `'/'` or `':'` | 0 | Adjacent values outside the range |
| `'+'`, `'-'`, `'a'`, `' '` or ` '\0'` | 0 | Not decimal digit characters |

The intended rule is a character check, not a conversion: it does not parse a
number, trim whitespace, accept signs, or change its input. For example,
`is_digit('4')` returns `1`, while `is_digit('-')` returns `0`. A negative
`char` value also returns `0`, because it cannot satisfy the lower and upper
digit bounds.

Keeping this rule in a small pure utility lets parsing code reuse the same
definition without depending on locale-sensitive classification or the
disallowed `isdigit` function.

<!-- section: planning -->
## How it was planned

The approved scope added one reusable core predicate in
`coders/src/utils/is_digit.c`, declared `is_digit(char c)` in the Utils section
of `main.h`, and registered the source in the deliverable Makefile. Acceptance
criteria cover all ten digits, adjacent and representative non-digit values
including a negative `char`, the public prototype, and the build/no-relink and
Norm requirements. The following subtask uses this helper in `parse_number`.

<!-- section: execution -->
## How it was executed

The implementation compares the character directly with the inclusive digit
range and returns a yes/no result. This keeps the helper deterministic and
independent of I/O, allocation, global state, or external classification
functions. The declaration is ordered before `is_space` in the shared Utils
section, and the Makefile includes the new source in the normal build.
