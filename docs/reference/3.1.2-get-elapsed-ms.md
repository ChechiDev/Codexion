## Measuring time since a shared start

`get_time_ms` provides an epoch timestamp in milliseconds. `get_elapsed_ms(start_ms)` turns that shared clock into a relative timestamp by subtracting the simulation's start time:

```text
elapsed_ms = current_epoch_ms - start_epoch_ms
```

For example, if the simulation starts at `1,800,000,000,000` ms and the current reading is `1,800,000,000,125` ms, the elapsed value is `125` ms. A log line can therefore use the same start for every coder and show `0` at the beginning of a run.

The clock is wall time, so it can move backwards after a system adjustment. A start value later than the current clock is clamped to zero, keeping successful elapsed timestamps nonnegative. If the underlying clock reports its `-1` failure sentinel, elapsed time propagates `-1` before doing subtraction; callers must treat that as an error rather than a duration.

This adapter takes a plain `long` instead of shared simulation state. It depends only on the time API, has no mutable state, and gives later sleep and logging adapters a common relative time scale.

<!-- section: planning -->
## How it was planned

The approved `3.1.2` spec declares one time adapter function and three production files: its source, the `Time` prototype in `coders/main.h`, and its build entry in `coders/Makefile`. Acceptance criteria bracket results with clock readings, check a past start after a delay, require a future start to return zero, and cover the build and Norm contract. The plan preserves the direct value-or-`-1` clock error convention established by `3.1.1`.

<!-- section: execution -->
## How it was executed

The implementation delegates the only clock read to `get_time_ms`, checks its failure sentinel before arithmetic, then clamps a future start to zero. This keeps system time access in the time adapter and leaves callers with a single relative timestamp function. The interface remains independent of `t_sim`, mutexes, and other shared state.
