## A coder owns its synchronization state

Each seat in the simulation maps to one coder. The coder record combines its public identity, the two neighboring dongle indices, per-coder compile state, and the synchronization needed to protect that state. Its simulation pointer is borrowed so the coder routine can later reach shared simulation state without copying it.

For four coders the ordered seat mapping is:

| Seat | Coder id | First dongle | Second dongle |
|---:|---:|---:|---:|
| 0 | 1 | 0 | 1 |
| 1 | 2 | 1 | 2 |
| 2 | 3 | 2 | 3 |
| 3 | 4 | 0 | 3 |

The single-coder case has only one dongle, so both indices are zero. Compile state starts at `last_compile_start = 0` and `compile_count = 0`. The zero timestamp gives EDF calculations a defined base before the first compile; later simulation logic updates these values under the coder mutex. The `thread` field is reserved for the phase that starts and joins coder threads; this initializer leaves it untouched.

Initialization behaves like a small transaction:

```text
validate pointers and seat ──> map dongles ──> initialize mutex ──> publish fields
         failure ──────────────── -1              failure ──────────── -1
```

All validation and mapping happen before the mutex or coder fields are changed. If mutex creation fails, the call returns `-1` without publishing any fields. On success, the caller owns the initialized mutex and must eventually release it through the matching coder teardown operation. The simulation pointer is stored only; it is not dereferenced.

<!-- section: planning -->
## How it was planned

Subtask 5.3.1 adds the coder type and one initializer in the adapter lifecycle module. Its declared files are the new `init_coder.c`, the shared header, and the deliverable Makefile. The acceptance criteria cover mapped fields and unlocked mutex state, preserving the thread field, the one-coder mapping, unchanged storage on invalid inputs, and independent mutexes. A forced mutex-initialization failure is covered by source review because it cannot be induced portably.

<!-- section: execution -->
## How it was executed

The initializer delegates ring arithmetic to the existing `get_dongle_pair` core API, keeping mapping rules in one place. It first validates the coder and simulation pointers, obtains the pair into local variables, and initializes the coder mutex. Only then does it assign the identity, indices, zeroed compile state, and borrowed simulation pointer. This ordering means invalid calls do not partially populate the record, and a failed mutex initialization has no other initialized resource to roll back.

The `init/` adapter row in [[docs/architecture.md]] now includes coder mutex setup in its lifecycle responsibility.
