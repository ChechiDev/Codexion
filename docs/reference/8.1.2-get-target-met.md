## Checking whether every coder met the compile target

The simulation is complete when every coder has completed at least the
configured number of compiles. For target `R`, the condition is:

```text
met = every coder i has compile_count[i] >= R
```

For example, with four coders and target 3, counts `3, 4, 3, 3` meet the
target. Counts `3, 4, 2, 3` do not: one coder is still below it. The configured
value matters; the check must work for targets other than 3, including `INT_MAX`.
A target of zero is already met, so it succeeds immediately without reading coder
state under mutexes.

`get_target_met` reads each `compile_count` while holding that coder's mutex,
then releases it before moving to the next coder. Thus it never holds two coder
mutexes at once. Compile counts only increase, so seeing every coder at or above
the target proves the target has been reached even if a coder completes another
compile during the scan. A negative result is a snapshot and may become stale
as a coder completes work; the monitor checks again on its next pass.

The function reports success with return value 0 and writes 0 or 1 through
`met`. Invalid input or a mutex error returns -1, and the output is not changed
on failure. The query does not change simulation or coder fields, log, or stop
the simulation; those actions belong to the monitor routine.

<!-- section: planning -->
## How it was planned

Subtask 8.1.2 adds a read-only monitor query in
[[coders/src/monitor/get_target_met.c]], its declaration in `main.h`, and its
build entry in the Makefile. The acceptance criteria cover below-target and
met-target scans, first and last coder positions, alternate and zero targets,
state preservation, mutex contention, and invalid inputs. Lock and unlock
failure handling, zero-target lock avoidance, and the restriction to coder
mutexes remain source-review checks because the harness has no fault injection.

<!-- section: execution -->
## How it was executed

Validation occurs before synchronization, and a zero target returns met without
locking. For a positive target, the implementation locks one coder mutex,
reads the count, unlocks, and stops at the first count below the threshold. It
publishes the result only after all required unlocks have succeeded. This keeps
the output unchanged on synchronization errors and avoids coupling the query to
logging, clock access, or stop handling. The monitor module is mapped in
[[docs/architecture.md]].
