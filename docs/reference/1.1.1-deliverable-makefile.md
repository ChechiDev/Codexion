## A deliverable Makefile

A Makefile turns source files into a repeatable build. For this subtask, the
deliverable is `coders/codexion`, built from the explicit source list in
`coders/Makefile` with the compiler and flags required by the subject.

The dependency chain is:

```text
main.c ──compile──> main.o ──link──> codexion
```

`all` names the default target and depends on `$(NAME)`. The executable depends
on its object files, and each object depends on its source. Make compares file
timestamps and runs only the commands needed to bring targets up to date. For
example, after a successful build, another `make -C coders` reports that there
is nothing to do and does not relink the executable.

The maintenance targets have distinct effects:

| Command | Effect |
| --- | --- |
| `make -C coders clean` | Remove object files and keep the executable. |
| `make -C coders fclean` | Remove object files and the executable. |
| `make -C coders re` | Clean fully, then build again. |

`make -C coders -n` prints the commands without executing them. The actual
compile and link use `cc` with `-Wall -Wextra -Werror -pthread`; `-I.` makes
headers in `coders/` available to the sources. The explicit `SRC` list keeps
the build scope visible as the project grows.

<!-- section: planning -->
## How it was planned

The approved subtask scoped the deliverable to `coders/Makefile`, the minimal
`coders/main.c` entry point, and the root `README.md`. Its acceptance criteria
cover building the executable and its command flags, no relink, each required
Make target, Norm compliance, and the README's required sections and build
instructions. No header dependency was planned yet because `main.h` belongs to
the following subtask.

<!-- section: execution -->
## How it was executed

The Makefile uses a single explicit source (`main.c`) and derives the object
list from it. Keeping the executable dependent on objects, with no recipe on
`all`, lets Make enforce the no-relink behavior naturally. The initial `main`
returns success so the deliverable can be built before simulation behavior is
introduced. The README explains the available build targets and postpones run
instructions until the program accepts arguments.
