## Releasing an initialized coder prefix

`free_coders` tears down an owned array of `t_coder` values. Its `count` is the
number of elements whose `init_coder` call succeeded, not necessarily the
array's capacity. That distinction makes partial initialization safe: if
initializing element `k` fails, only elements before `k` contain live coder
mutexes and may be destroyed.

For example, an array with four slots where only the first two were initialized
must be released with `free_coders(coders, 2)`. The last two slots are outside
the initialized prefix and are never read. Teardown runs from the end of the
prefix toward the beginning:

```text
initialized:  [ coder 0 ][ coder 1 ][ unused ][ unused ]
destroy order:                  1  →  0
free array:     once, after all destroy attempts
```

This is best-effort cleanup. A failed `destroy_coder` does not prevent attempts
on the remaining initialized elements, and the allocation is still freed. The
return value reports whether all destroys succeeded (`0`) or any failed (`-1`).
Invalid input is checked before touching ownership: a negative count, or a NULL
array with a positive count, returns `-1` without freeing anything. A NULL
array with count zero is a valid no-op. For any other valid call, ownership of
the allocation is consumed, including when count is zero; callers must not use
the pointer afterward.

<!-- section: planning -->
## How it was planned

The approved scope adds `free_coders` in the cleanup adapter, declares it in
the single public header, and registers its source in the deliverable Makefile.
Acceptance criteria cover a fully initialized array, a partially initialized
prefix, zero count, NULL inputs, and rejection of a negative count without
consuming the allocation. The approved code review check also requires reverse
order destruction, continued cleanup after a destroy failure, and one final
array free.

<!-- section: execution -->
## How it was executed

The implementation follows the same lifecycle contract as `free_dongles`:
validate before access, call `destroy_coder` for each initialized element in
reverse order, remember any failure while continuing the loop, then free the
owned array once. The `sim` pointers inside coders are borrowed references, so
this operation leaves simulation state alone. Thread joining is outside this
function's contract; callers must satisfy `destroy_coder`'s preconditions.

The `cleanup/` architecture map now includes coder arrays among the resources
owned by that adapter.
