## Decide whether one dongle may be taken

A dongle is ready for a particular coder only when three independent conditions
hold at the same time:

1. The coder is at the head of that dongle's priority queue.
2. The dongle is available.
3. Its cooldown has elapsed since the last release.

In compact form:

```text
ready = (queue head belongs to coder)
     && (dongle is available)
     && (never released || cooldown has elapsed)
```

For example, suppose coder 3 is the queue head and the dongle was released at
1000 ms with a 50 ms cooldown. At 1049 ms the cooldown is still active, so the
dongle is not ready. At 1050 ms, it is ready if it remains available. If coder
1 is the queue head instead, coder 3 is not ready even after the cooldown ends:
the queue head protects FIFO or EDF ordering.

The value `released_at == -1` means the dongle has never been released, so
there is no cooldown to wait through. For a released dongle, elapsed time is
checked only when `now >= released_at`; then subtracting the two non-negative
times cannot underflow. This also avoids adding the cooldown to the release
time, which could overflow at large values.

The predicate is pure and read-only. Its caller supplies elapsed time and holds
the dongle mutex while its availability, release time, and heap are being
examined. Invalid inputs return 0, the safe answer meaning “not ready.”

<!-- section: planning -->
## How it was planned

The approved spec places this deterministic arbitration rule in the core
`policy/` module. Its declared production files are the predicate source, the
Policy prototype in `coders/main.h`, and the source entry in `coders/Makefile`.
Acceptance criteria cover first use, queue-head selection, unavailable state,
cooldown boundaries, overflow limits, read-only behavior, and invalid input.
The later acquisition operations call this rule while holding the dongle lock.

<!-- section: execution -->
## How it was executed

The implementation validates arguments before inspecting the heap, obtains the
head through the existing read-only `get_head_request` API, and combines head
ownership with availability and cooldown eligibility. It accepts an explicit
`now` value instead of reading the clock, which keeps the policy deterministic
and lets the acquisition layer own timing and synchronization. The architecture
map now identifies readiness alongside request ordering in `policy/`.
