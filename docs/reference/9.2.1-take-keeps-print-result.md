## Preserve the cause when logging an acquisition

Taking dongles is a small transaction: the coder acquires its required dongle or pair, prints one acquisition line per dongle, and must give the dongles back if a line cannot be printed. The print operation has three meaningful outcomes: success (`0`), a normal stop already observed (`1`), or a real output failure (`-1`). Keeping that result lets the caller report the right outcome without guessing from a later snapshot of shared state.

| Print result | Meaning | Acquisition result after successful release |
|---|---|---|
| `1` | The simulation was stopped before the line was printed. | `0`, with `*taken == 0` |
| `-1` | Printing failed. | `-1`; `*taken` is left untouched |
| either nonzero, release fails | Dongles could not be returned cleanly. | `-1` |

The distinction matters when a failed write and a stop overlap in time. A later read of `sim.stopped` cannot tell which event caused the failed acquisition log. The original print result can:

```text
acquire dongles
    ├─ print returns 0  → acquisition succeeds
    ├─ print returns 1  → release once → ordinary stop result
    └─ print returns -1 → release once → preserve real error
```

On an error, returning the dongles restores shared availability while leaving the caller's output parameter unchanged. A stop indication is the ordinary “not taken” case, so it reports success from the helper with zero dongles taken. The later coder routine can therefore mark the simulation failed only for an actual error.

## How it was planned

The orchestration subtask declares only `coders/src/coder/take_coder_dongles.c` for modification. Acceptance criteria cover pair acquisition and logging on a running simulation, a pre-stopped simulation, a real output error, the one-coder path, and a deterministic failed write that coincides with the stop flag. The last case protects the central contract: an actual print error remains an error even if the simulation is stopped by the time the caller handles it. No new public identifier or README change was planned.

## How it was executed

The printing helper now returns the first nonzero `print_state` result unchanged. The cleanup path receives that result directly and releases the acquired dongles once. It maps the stop result to “not taken,” but preserves a negative result as a real failure regardless of a later stop state. This keeps error classification at the boundary where its cause is known and avoids adding a second, racy inference from shared state. The existing API and successful acquisition behavior remain unchanged.

## Problems & resolution

The first plan review found that no acceptance criterion distinguished this behavior from the existing wrapper behavior. The plan was revised to add AC5, using a test-defined `write` stub to force a failed write while setting the stop flag deterministically. The revised plan was approved. No implementation blocker remained.
