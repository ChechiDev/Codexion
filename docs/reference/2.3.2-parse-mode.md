## Recognizing an exact scheduler mode

The scheduler argument chooses how competing coder requests are ordered. This parser recognizes the two spellings the subject permits: lowercase `fifo` and lowercase `edf`. The match is exact across the entire string and is case-sensitive; whitespace normalization belongs to numeric parsing and does not apply here.

| Input | Result | Output value |
|---|---|---|
| `fifo` | success (`0`) | `MODE_FIFO` |
| `edf` | success (`0`) | `MODE_EDF` |
| `FIFO`, ` edf`, `edff`, or `rr` | failure (`-1`) | unchanged |

On success, `*out` receives the selected enum. On any failure, the caller's output remains untouched. A null input string or output pointer is rejected before comparison or assignment. This gives later configuration parsing a small contract: it can distinguish an accepted mode from any malformed scheduler without printing or changing the argument text.

<!-- section: planning -->
## How it was planned

Subtask 2.3.2 declares three production files: a new parser source, the public prototype in `main.h`, and the source list in the deliverable Makefile. Its acceptance criteria cover both recognized modes, rejected case/whitespace/prefix/suffix/other values with output preservation, null pointers, and a successful build with clean Norm output. The spec requires `strcmp` for whole-string matching and explicitly excludes trimming.

<!-- section: execution -->
## How it was executed

The parser compares against each allowed literal with `strcmp`. It checks both pointers before using either, and assigns the enum only after a recognized comparison. This keeps the core function pure and makes failure safe for callers that already hold a mode value. The parser is a separate translation unit with its declaration in the shared header and source entry in the Makefile, ready for `parse_config` to compose in the next subtask.
