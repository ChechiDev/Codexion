## Declaring a shared log writer

A log line has a small, repeated lifecycle: obtain elapsed time, turn the coder
number and message into bytes, then send the complete line to standard output.
Ordinary state messages and the terminal burnout message both need this same
sequence. Giving it one API lets callers share the output contract without
reimplementing the formatting and write steps.

The `print_log_line` contract is:

```c
int print_log_line(t_sim *sim, int coder, const char *text);
```

The caller holds `log_mutex` for the duration. The helper reads elapsed time
from `sim->start_ms`, formats into a bounded local buffer, and makes exactly one
`write` to file descriptor 1. For example, coder 2 and the text `is debugging`
produce a line like:

```text
401 2 is debugging
```

It returns `0` only when the write accepts the full line. Clock, formatting, or
write errors return `-1`; a clock or formatting failure produces no write. The
helper does not acquire locks, inspect the stop flag, or change simulation
state. Those rules keep synchronization and message acceptance with the caller
while centralizing line construction and output.

```text
caller holds log_mutex
       │
       ├── print_log_line: elapsed time → bounded formatting → one write
       │
caller releases log_mutex
```

<!-- section: planning -->
## How it was planned

The approved scope is intentionally header-only: declare the helper and its
caller-lock and one-write contract in the existing `Log` section of
`[[coders/main.h]]`. The declaration prepares the following extraction subtask
to replace the duplicated output sequence used by `print_state` and the
burnout logger. Acceptance retains the existing `print_state` behavior and
checks the deliverable build and Norm; the code review checks the precise
declaration and the absence of implementation changes.

<!-- section: execution -->
## How it was executed

The header declares the shared adapter API without adding implementation or
changing observable behavior. Keeping the caller responsible for holding
`log_mutex` means the helper can be reused inside an already serialized logging
operation without recursive locking. Restricting it to timestamp acquisition,
line construction, and one write gives both callers the same output path while
leaving stop decisions with their owning operations. The `Updated:` header
metadata was refreshed as required by the project convention.
