## Inserting a request into a min-heap

A binary min-heap stores its highest-priority request at index 0. For any item
at index `i > 0`, its parent is at `(i - 1) / 2`. The heap invariant is that a
child never precedes its parent according to
[[docs/reference/4.1.1-is-request-before.md]].

To insert a request, append it at the first unused slot and move it upward only
while it precedes its parent:

```text
Before: [ {key: 5, ticket: 1}, {key: 8, ticket: 2}, {key: 9, ticket: 3} ]
Push:   {key: 3, ticket: 4}
Append: [ 5/1, 8/2, 9/3, 3/4 ]
Sift:   [ 3/4, 5/1, 9/3, 8/2 ]
```

Each swap moves the new item one level closer to the root. A heap with `n`
items has at most `log2(n)` levels, so insertion takes logarithmic comparisons
and swaps. The root is then the request to serve first, whether the key came
from FIFO arrival order or an EDF deadline.

The comparator is strict: equivalent requests do not swap. This preserves the
existing heap arrangement when priorities tie; ticket ordering itself is
handled centrally by the comparator. A successful push copies the caller's
request into heap-owned storage. Invalid pointers and a full heap fail without
changing the heap. The caller owns synchronization; in arbitration code it must
hold the dongle mutex while modifying that dongle's heap.

<!-- section: planning -->
## How it was planned

Subtask 4.3.1 declares `push_request` in the core heap module, its prototype in
[[coders/main.h]], and registration in [[coders/Makefile]]. The acceptance
criteria cover insertion into an empty heap, successive minimum heads, the
heap invariant and contents, FIFO/EDF ties, unchanged state on full or invalid
input, copy-by-value behavior, extreme keys and larger heaps, plus build and
Norm integration. The spec requires validating arguments and capacity before
writing, using only the existing comparator, and keeping allocation, locking,
clock and output outside this core operation.

<!-- section: execution -->
## How it was executed

The implementation places the request copy at `items[size]`, increments the
size, then uses a private `sift_up` helper to compare the new item with its
parent. It swaps only when `is_request_before` says the child has higher
priority. This keeps the ordering rule in one policy function and makes the
heap operation a deterministic transformation of caller-owned storage. Full
and null checks happen before any write, preserving the heap on failure. The
existing `heap/` architecture entry already describes push as a heap operation,
so no cross-cutting architecture change was needed.
