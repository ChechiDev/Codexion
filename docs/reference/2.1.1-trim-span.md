## A trimmed view into a string

Whitespace around a value often needs to be ignored without changing the original argument. A span represents the useful part of a string as a pointer and a length. The pointer refers to the original bytes, so trimming needs neither a new allocation nor a copy.

For example, given `"     0007     "`, the returned span starts at the first `0` and has length 4. It describes `0007`; the leading and trailing spaces remain in the original string. A parser can then validate those four bytes and decide whether the value is acceptable.

The helper treats the six C-locale whitespace bytes as trim characters: space, tab, newline, vertical tab, form feed, and carriage return. It removes them only from the two ends. Thus `"  fi fo  "` gives a span of length 5 containing `fi fo`; interior whitespace is preserved for the caller to accept or reject.

| Input | Span content | Length |
|---|---|---:|
| `"fifo"` | `fifo` | 4 |
| `"  edf\t"` | `edf` | 3 |
| `"   "` | empty | 0 |
| `NULL` | no pointer | 0 |

This separation keeps normalization reusable while leaving meaning to the next parser. Numeric parsing can accept surrounding whitespace, while scheduler parsing can enforce its own exact spelling rule.

<!-- section: execution -->
## How it was executed

The implementation advances a pointer past leading whitespace, then measures the remaining string and shortens that length past trailing whitespace. A small private predicate recognizes the six specified bytes. The resulting span points into the caller's string and does not alter it, allocate memory, or depend on I/O or threads. The API type and prototype are in the shared header, and the source is included in the deliverable build.
