## Freeing a partially or fully initialized dongle array

An initialized dongle owns several resources: its request heap, condition variable, and mutex. An array also owns the allocation containing all dongles. Teardown therefore has two levels: destroy the live elements, then release the outer allocation.

The `count` argument is the number of **leading elements that were successfully initialized**, not the allocated array capacity. This makes one function serve both normal shutdown and rollback:

| Situation | `count` | Elements destroyed |
|---|---:|---|
| Three dongles all initialized | 3 | 2, 1, 0 |
| Initialization failed at element 2 | 2 | 1, 0 |
| Allocation succeeded, first initialization failed | 0 | none; array is still freed |

Each element is destroyed in reverse initialization order. If destroying one element reports an error, teardown continues so later elements and the array allocation are still released. The result is `-1` if any element failed; otherwise it is `0`.

Invalid arguments are rejected before touching ownership: a negative count, or a null array with a positive count, returns `-1` and leaves the caller's data alone. `free_dongles(NULL, 0)` is valid. With valid input, the array is always freed, so callers must discard the pointer after the call.

```text
array:   [ dongle 0 ][ dongle 1 ][ dongle 2 ]
destroy:       2  ───────→  1  ───────→  0
free:      release the array allocation once
```

The caller must ensure each live dongle is unlocked, has no waiting thread, and is no longer in use before teardown; this function does not coordinate with simulation threads.

<!-- section: planning -->
## How it was planned

The approved adapter subtask declares one public cleanup function, its `main.h` prototype, and the `Makefile` source entry. Acceptance criteria cover full and partial arrays, zero initialized elements, null input, and negative counts. The code review check also requires reverse destruction, best-effort completion after an element failure, and exactly one array free. The same operation is intended as the rollback path for `init_dongles` and the array teardown path used by later simulation cleanup.

<!-- section: execution -->
## How it was executed

The implementation validates the count and pointer before indexing or freeing, then walks the initialized prefix backward through the existing `destroy_dongle` API. It remembers any destruction failure while continuing the walk, and releases the allocation once after all attempts. This preserves a single ownership rule for callers: valid input transfers the array to the function, even when an element teardown reports an error.
