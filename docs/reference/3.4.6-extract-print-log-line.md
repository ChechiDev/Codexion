## One shared path from event to output

The logger has two distinct jobs: deciding whether an event may be logged, and
turning an accepted event into bytes on standard output. `print_state` owns the
first job because it must coordinate the stop flag and preserve output order.
`print_log_line` owns the second: it reads elapsed time, asks the pure
`build_log_line` formatter for the bytes, and sends those bytes to file
descriptor 1.

For example, the event text `is compiling` for coder 7 might produce:

```text
1204 7 is compiling
```

The responsibilities fit together as follows:

```text
print_state: acquire log lock → check stopped → print_log_line → release log lock
                                              │
                                              ├─ get elapsed milliseconds
                                              ├─ build_log_line into local bytes
                                              └─ one write(1, bytes, length)
```

The helper takes no mutex and does not inspect `stopped`; this keeps the
serialization policy with its caller and permits the caller to hold
`log_mutex` across the complete decision and output sequence. It validates
through the formatter, returns `0` only when the whole line is accepted by one
write, and returns `-1` for a clock, formatting, or write failure. A short
write can leave a partial line, and there is no retry. A single unbuffered
write makes completed lines immediately visible to pipe readers.

<!-- section: planning -->
## How it was planned

The approved spec declares a new `print_log_line` source, a refactor of
`print_state.c`, and one build-list change. Its eight acceptance criteria cover
the caller-held lock contract, timestamp bounds, immediate pipe visibility,
absence of locking and stop checks in the helper, invalid input, write errors,
the sealed state-printer regression, and build integration. The shared path
reuses `get_elapsed_ms` and `build_log_line` rather than duplicating time and
formatting logic.

<!-- section: execution -->
## How it was executed

`print_log_line` builds into a local fixed-size buffer and performs the
timestamp, formatting, and single-write sequence. `print_state` retains its
lock order, stop check, and unlock handling while delegating the output step.
This leaves one implementation of the serialized line format and keeps the
decision to accept an event at the adapter that owns that decision.
