## Joining a simulation's threads

Creating a thread starts concurrent work; joining it waits for that work to
finish and collects its termination. A simulation has one monitor thread and
one worker thread per coder. The lifecycle join operation receives the count
of coder threads that were actually created, waits for those coders in index
order, and then waits for the monitor.

The count makes the same operation fit both complete and partial startup:

| Situation | `coders` | Threads joined |
|---|---:|---|
| Normal run with four coders | 4 | coder 0, coder 1, coder 2, coder 3, monitor |
| Startup failed after two coders | 2 | coder 0, coder 1, monitor |
| Only monitor has started | 0 | monitor |

The caller must first arrange for every target thread to finish. Joining does
not request a stop, wake condition-variable waiters, or free simulation state.
This separation matters: shutdown policy belongs to the caller, while this
function only waits for thread completion. The caller must also retain the
`t_sim` storage until every join succeeds, because the running threads may
still refer to it.

Invalid input is rejected before any thread is joined. For valid input, each
join is attempted even if an earlier one reports an error, and the result is
`-1` if any join failed:

```text
join coder 0 ─┐
join coder 1 ─┼─> attempt all joins ─> 0 if all succeed, otherwise -1
join monitor ─┘
```

A failed join is an unrecoverable lifecycle error: a `-1` does not prove all
threads ended, so the caller must keep the simulation storage alive and must
not free or reuse it. Trying the remaining joins reduces the chance of leaving
another thread running, but cannot make a failed join safe to ignore.

<!-- section: planning -->
## How it was planned

The subtask adds one lifecycle orchestration function and declares three
production files: its implementation, the public prototype in `main.h`, and
the Makefile source list. Acceptance criteria cover waiting for all threads,
partial startup, monitor-only operation, and invalid counts that must return
without joining held threads. The plan also requires trying every join and
checking its result; that part is verified by source review because a portable
failed-join setup cannot safely be forced in a test.

<!-- section: execution -->
## How it was executed

`join_threads` validates the simulation pointer and coder count first. It then
calls `pthread_join` for the requested coder range and the monitor, preserving
an error result while continuing through the remaining handles. It neither
controls shutdown nor changes shared state, leaving the start-failure and
normal-run callers responsible for stopping and waking threads before they
wait. The architecture maps now include `lifecycle/` as the owner of thread
startup, joining, and end-to-end run coordination.

## Problems & resolution

The implementation's first `make verify` attempt encountered the existing
`test_1.1.1` output-capture limit: `make -C coders re` exceeded its fixed
8192-byte buffer after a source was added. The oracle was repaired separately
by draining output through EOF while retaining only bytes that fit. The
subtask code review and supplied close check are approved and green.
