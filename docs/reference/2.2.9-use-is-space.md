## Reuse the whitespace predicate

Trimming removes whitespace at the edges of a text view while preserving its
interior. The project defines whitespace as exactly space and the five
characters tab, line feed, vertical tab, form feed, and carriage return. The
`is_space` utility owns that definition, so `trim_slice` can apply one shared
rule at both ends:

```text
"  alpha\t beta  "
  └─ trim leading spaces      trim trailing spaces ─┘
      "alpha\t beta"
```

The tab inside the text remains. `trim_slice` returns a non-owning view into
the original string; it neither edits nor copies the input. Empty and
all-whitespace strings produce a view with length zero, and `NULL` maps to
`{NULL, 0}`. Other bytes are retained: for example, `\x01` and `\x7f` are not
part of this whitespace set.

Using the helper in both boundary loops keeps classification consistent. If
the project's whitespace definition changes, the predicate is the single
place to update rather than duplicating a character list in each caller.

<!-- section: planning -->
## How it was planned

The approved spec declares a structural refactor in the core utility
`coders/src/utils/trim_slice.c`. Its acceptance criteria preserve the behavior
established by 2.2.6, check that non-whitespace boundary bytes survive, and
retain build and Norm coverage. The code review check is source inspection:
both loops must call `is_space`, with no handwritten whitespace condition.

<!-- section: execution -->
## How it was executed

Both the leading and trailing scans now delegate character classification to
the existing `is_space` helper. The slice boundaries, `strlen` use, integer
conversion, and ownership contract remain as before. This keeps `trim_slice`
focused on locating the view while `is_space` defines which characters count
as whitespace.

<!-- section: problems -->
## Problems & resolution

The first acceptance run exposed an incorrect expected offset: the test input
has seven leading whitespace characters, not six. The plan gate corrected the
expectation to `input + 7` and resealed the oracle; the behavior and
implementation did not need adjustment.
